Kruk2/jasna

Python 初掲載 2026-10-19（GitHub Trending 12位） GitHub ↗

動画や画像のモザイクをGPUで検出・復元する無料のアプリとコマンドラインツール

何ができるか

  • 動画内のモザイクを見つけて復元し、それ以外の部分には手を加えない。
  • 高速な BasicVSR++（無料）と、低速だがより細部まで復元できる LTX（支援者向け・NVIDIA のみ）の2種類の復元モデルを選べる。
  • Segment Editor で、プレビューを見ながら復元したい区間だけを選んで処理できる。
  • VR180 動画や静止画（支援者向けの SD 1.5 モデル）にも対応している。
  • Video Player を使うと、ファイルを書き出さずに復元しながらリアルタイムで再生できる。
  • GUI アプリに加えてコマンドラインからも、動画1本・画像1枚・フォルダ一括の処理ができる。

なぜ注目されているか

README のベンチマークでは、3分22秒の動画の復元が参考元の Lada 0.11.0 より 3.4〜4.7 倍速いと示されている。推測 動画のデコードからエンコードまでほぼ全工程を GPU 上で処理する設計による速度と、手軽に使える GUI が注目を集めていると考えられる。

どんな人に役立つか

NVIDIA（GTX 16 シリーズ / RTX 20 シリーズ以降）や AMD Radeon RX 7000/9000 の GPU を持ち、動画のモザイク復元を手元で高速に行いたい人に向く。動画処理パイプラインを GPU で組む実装例として、開発者がソースを読むのにも役立つ。

技術的なポイント

  • 処理は GPU でのデコード（NVDEC/AMF）→ モザイク検出（既定モデル rfdetr-v6）→ 時間方向の追跡とクリップ化 → BasicVSR++ による 256x256 単位の復元 → 元フレームへの合成 → GPU エンコード（NVENC/AMF）という流れで行われる。
  • クリップはシーンの切れ目で区切られ、少しずつ重ねて処理することでクリップ間の継ぎ目が目立たないようにしている。
  • 初回実行時にモデルを使用中の GPU 向けに最適化して model_weights フォルダに保存し、以降はそれを再利用する（NVIDIA のみ、初回は15〜60分ほどかかる）。
  • LTX は拡散モデル（ノイズから画像を生成するタイプの生成モデル）を使い、検出・準備・復元・保存の4パスで動画を処理する。
  • UNet 4x、RTX Super Res、Topaz TVAI による任意の二次復元で、復元部分をより大きく鮮明にできる。

試し方

  1. 自分の OS と GPU に合ったリリースをダウンロードする。
  2. 中国語・日本語・アクセント付き文字などを含まないパスのフォルダに展開する。
  3. Windows は jasna.exe、Linux NVIDIA は jasna、Linux AMD は run_jasna_amd.sh を実行してアプリを起動する。
  4. 動画を追加して設定を選び、画面下部の ▶ ボタンを押す（初回は GPU 向けのモデル準備に時間がかかる）。
jasna --input input.mp4 --output output.mkv
jasna --input photo.png --output restored.png
jasna --input input_folder --output output_folder
jasna --help
