NyxFoundation/nyxis

初掲載 2026-10-27（はてなブックマーク 2位） GitHub ↗

認可の安全性を形式的に証明済みのLean製バックエンドフレームワーク

何ができるか

  • CedarスキーマとポリシーだけでHTTPリクエストの認可ルールを定義でき、Leanのコードを書く必要がない
  • lake buildのたびに「認証済みユーザーが正当な権限外のデータにアクセス・変更・削除できない」という数学的証明を自動検証する
  • read・list・insert・update・deleteのデータ操作と、ファイルストレージ・メール通知・外部API呼び出しをすべて認可層経由で制御できる
  • ハンドラーはSupabase Auth（JWT認証サービス）のJWTトークンから主体を取得するため、ハンドラーコード内で認証情報を偽造できない
  • AIツール（Claude Codeなど）がハンドラーコードを生成しても、証明が通らない限りビルドが失敗するため安全に利用できる

なぜ注目されているか

AIエージェントが生成するWebアプリコードの認可ロジックに潜むバグは従来のテストでは見逃されがちだが、このフレームワークは形式証明（定理証明）によって数学的に安全性を保証する点が新しい。v0.1.0リリース直後で実験的な段階ながら、AIコーディング全盛期における認可の信頼性という課題に正面から取り組んでいるとして注目されている。

どんな人に役立つか

AIエージェントを使ってWebアプリを一人で開発するソロ開発者や、認可ロジックのセキュリティ保証に不安を感じているエンジニアに向いている。また、形式検証や定理証明（Lean 4）に興味がある研究者・学生にとっても実用的なユースケースとして参考になる。

技術的なポイント

  • Lean 4（マイクロソフト研究所が開発した定理証明支援系兼プログラミング言語）でコアロジックと証明を記述している
  • Cedar（AWSが開発したポリシー言語）でスキーマ定義とアクセス制御ポリシーを記述し、エンティティ型がDBテーブルに対応する
  • 主定理 Nyxis.Runtime.authorization_safety がすべての認可安全性を保証しており、lake buildのたびにLeanカーネルが証明を再検査する
  • データベースはPostgreSQL（Supabase）を使用し、認証はSupabase AuthのJWTトークンに依存することで接続コードが証明の前提条件を守る設計になっている
  • 依存ライブラリはSHA256で固定管理されており、scripts/prepare-dependencies.pyで取得・検証するためサプライチェーン攻撃への耐性がある

試し方

  1. Lean 4（elan経由）、Python 3.12以上、OpenSSL CLI、Cコンパイラ、libpqとlibcryptoの開発ファイルをインストールする
  2. リポジトリをクローンしてprepare-dependencies.pyでピン留め済み依存ライブラリを取得する
  3. lake buildでコア・証明・テストをビルドし、証明が通ることを確認する
  4. examples/bulletin-board/を参考にCedarスキーマとポリシーを書き、ハンドラーを実装して動作確認する
python3 scripts/prepare-dependencies.py
lake build
