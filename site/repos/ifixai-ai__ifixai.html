ifixai-ai/iFixAi

Python 初掲載 2026-10-19（Star History 15位） GitHub ↗

AIエージェントが本来の仕事をきちんとしているかを短時間で監査する診断ツール

何ができるか

  • 権限外のツール利用、権限昇格、プロンプトインジェクション（悪意ある指示の混入）への耐性などを、60種類の検査で調べます。
  • 既定では重要度の高い10検査を実行し、--full-run で60検査すべてを実行できます。
  • 結果を Fabrication、Manipulation、Deception、Unpredictability、Opacity の5つの柱にまとめ、A〜F の成績を付けます。
  • 対話式ウィザード、明示的なコマンドライン引数、Claude Code や Codex のプラグイン（スキル）の3通りで実行できます。
  • OpenAI 互換の HTTP エンドポイントを持つ自作エージェントを、そのまま検査対象にできます。
  • レポートを JSON と Markdown で ./ifixai-results/ に出力します。

なぜ注目されているか

README では、既存の評価・レッドチーミング（攻撃者視点での検証）・監視ツールは主に技術的な能力を見ており、エージェントが業務上の目的や組織の決まりどおりに動いているかには答えられないと述べ、iFixAi はそれに120秒未満で答えるとしています。リポジトリページでは約3万のスターを集めています。推測 AIエージェントを業務に組み込む企業が増え、安全性や統制の確認手段が求められていることが注目の背景と考えられます。

どんな人に役立つか

業務用のAIエージェントを開発・運用し、権限管理やポリシー違反、情報漏えいのリスクを公開前に確認したい開発者やリスク管理の担当者に向いています。

技術的なポイント

  • Python 3.10 以上で動き、検査したいプロバイダごとに pip の追加パッケージ（例: ifixai[openai]）を入れて使います。
  • 検査対象とは別ベンダーの LLM が採点役（ジャッジ）を務めることで、自己採点ではない引用可能な成績になる仕組みです。
  • 複数のジャッジを使う場合は、判定が割れたら fail、partial、pass の順に厳しい側を採用します。
  • 独自の環境で動くエージェントは、ChatProvider.send_message という1つのメソッドを実装したアダプタで接続できます。
  • キーもネットワークも不要なモック（mock）プロバイダで、仕組みが動くかを数秒で確認できます。

試し方

  1. 検査したいプロバイダ用の追加パッケージ付きで ifixai をインストールします。
  2. ifixai setup の対話式ウィザードで、プロバイダ、モデル、ジャッジ、検査セットを選びます（設定は ifixai.yaml に保存されます）。
  3. ifixai run を実行すると、レポートが ./ifixai-results/ に出力されます。
  4. APIキーなしで試すなら、モックプロバイダで実行します（同梱の既定データにはわざと欠陥が入っているため、不合格の結果が出ます）。
pip install "ifixai[openai]"
ifixai setup
ifixai run
ifixai run --provider mock --api-key not-used --eval-mode self
