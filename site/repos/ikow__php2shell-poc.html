Python 初掲載 2026-10-23（Trendshift 17位） GitHub ↗

PHPのセッションアップロード進捗機能を悪用した認証不要RCE脆弱性（CVE-2026-109618/109619）の検証・検出ツールキット

何ができるか

  • 5種類のRCEエクスプロイトチェーン（Chain A〜E）を収録し、セッションインジェクションからOOMメモリ破壊まで多様な攻撃経路を網羅している。
  • Suricata/Snort・Sigma・ModSecurity・OpenResty Luaなど複数形式の検出ルールを提供し、IDS/WAF/SIEMへ即座に展開できる。
  • Docker Composeで構築できる検証用ラボ環境（PHP-FPM + nginx + Apache mod_php）が付属している。
  • Chain A・B・Cのエクスプロイトスクリプト（Python/PHP）が公開されており、コマンド一つでRCEを再現できる。
  • INI設定（session.upload_progress.enabled = Off）や緊急パッチバージョンなど、具体的な緩和策も詳述している。

なぜ注目されているか

推測 PHP 5.4（2012年）から14年間存在した認証不要のRCE脆弱性であり、世界のウェブサイトの78%（WordPressやJoomlaなど）に影響するとされるため、セキュリティ研究者や運用者の注目度が非常に高い。CVSS9.2のクリティカル評価でChain Dはゼロ依存・前提条件なしの完全なpre-auth RCEであるため、影響範囲の広さと深刻さから急速に拡散した。

どんな人に役立つか

ペネトレーションテスターやセキュリティ研究者が脆弱性の仕組みを学び、許可された環境で検証する用途に向いている。WAF・IDS管理者は検出ルールをすぐに取り込める。サーバー管理者やPHP利用企業のエンジニアには、パッチ適用前の緩和設定の参考になる。

技術的なポイント

  • PHP内部のsession.upload_progress機能とZendエンジンのOOMバイルアウト（longjmp）を組み合わせた複数のRCEチェーンを実装している。
  • Chain BはEG()（Zendのグローバル状態）経由でzif_systemのアドレスを探索し、/proc/self/memでハンドラを上書きするUAF（use-after-free）攻撃を利用する。
  • Suricata・Sigma・ModSecurity・OpenResty Luaの4形式でシグネチャを提供し、異なるセキュリティ製品に対応できる。
  • Docker Composeによる再現環境で、各チェーンの検証スクリプトをワンコマンドで実行できる構成になっている。

試し方

  1. リポジトリをクローンし、lab/ディレクトリでdocker compose up -dを実行して検証ラボを起動する。
  2. poc/verify_session_injection.pyなどの検証スクリプトでチェーンが再現できることを確認する。
  3. exploit/chain_a_session_lfi.pyで実際のRCEを試す（必ず許可された環境で実施）。
git clone https://github.com/ikow/php2shell-poc.git && cd php2shell-poc
cd lab && docker compose up -d
python3 ../poc/verify_session_injection.py --target http://127.0.0.1:18080
python3 ../exploit/chain_a_session_lfi.py --host 127.0.0.1 --port 18080 --command 'id'
