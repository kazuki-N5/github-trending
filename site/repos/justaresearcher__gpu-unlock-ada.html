RTX 4090等のテンソル演算制限をLinuxで解除するカーネルモジュール

何ができるか

  • Linuxカーネルモジュールとしてinitramfsで動作し、NVIDIAドライバがバインドする前にSMスピードセレクトオーバーライドを適用する。
  • RTX 4090（10de:2684）でFP16/FP32およびBF16/FP32テンソル命令スループットを約2倍（約165→330 TF/s）に向上させることを確認している。
  • RTX 4070 Ti SUPER（10de:2705）ではFP16/FP32とTF32/FP32の発行レートが約2倍になることを確認している。
  • RTX 4060 Ti 16GB（10de:2805）は実験的サポートで、SM速度レジスタの変更は確認済みだが同一カードでのベースライン比較は未実施。
  • ファームウェアペイロードをSHA-256で検証し、FLR（Function Level Reset）を実施してからNVIDIAドライバを起動させる安全手順を実装している。
  • ファームウェアはビルド時にローカル生成・ハッシュ検証されるため、プリビルドバイナリは配布されない。

なぜ注目されているか

コンシューマー向けGPUにハードウェアレベルで制限されているテンソル演算のスループットをソフトウェアで解除できる稀有なツールであり、ローカルAI推論や研究用途でのコスト対性能比向上に直結する。GPU内部のSMスピードセレクト機構をLinuxカーネルモジュールとして操作する技術的アプローチが注目されている。推測 NVIDIA公式サポート外の操作であるため、動作保証やドライバ更新後の互換性には注意が必要と考えられる。

どんな人に役立つか

ローカルでLLM推論や機械学習ワークロードを実行しており、RTX 4090などのコンシューマーGPUのテンソル演算性能を最大化したい研究者や開発者に向いている。Linuxカーネルモジュールのビルドやinitramfsの設定経験がある中級以上のユーザーを想定している。

技術的なポイント

  • カーネルモジュールはinitramfsステージで実行され、NVIDIAドライバのバインド前にGPUのファームウェアトランザクションを実行する。
  • AD102ペイロードとデバッグブーター解析はTOTORONG/AD103_win_unlockerに由来し、LinuxモジュールはZagitta/gpu-unlockから派生している。
  • ビルド時にピン留めされたNVIDAの入力ファイルをダウンロードしてハッシュ検証することでサプライチェーン攻撃を防ぐ設計になっている。
  • カーネルコマンドラインオプション（gpu_unlock.targets=）でターゲットGPUのPCIアドレスを指定して動作させる。
  • カーネルモジュールとパッケージングはGPL-2.0-only、NVIDIAファームウェアはNVIDIA独自ライセンスが適用される。

試し方

  1. リポジトリをクローンしてソースからビルドする（make install、またはArch/Debian/RPM向けターゲットを使用）。
  2. 初回試行前にコールドパワーオフ（完全電源断）を行い、ウォームリブートを避ける。
  3. カーネルコマンドラインにgpu_unlock.targets=をPCIアドレスとともに追加してターゲットGPUを指定する。
  4. initramfsにモジュールを組み込み、NVIDIAドライバより前にロードされるよう設定する。
make install
