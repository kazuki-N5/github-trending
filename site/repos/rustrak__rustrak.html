rustrak/rustrak

Rust 初掲載 2026-11-22（Trendshift 16位） GitHub ↗

Rustで書かれた自己ホスト型のSentry互換エラートラッキング・ログ・AIエージェントトレース統合監視ツール

何ができるか

  • 既存のSentry SDK（エラー収集ライブラリ）のDSN（接続先URL）を変更するだけで移行でき、エラーを自動グループ化してIssue管理できる
  • AIエージェントの実行トレース（呼び出しウォーターフォール・モデル/ツール使用状況・レイテンシ分位数）を専用画面で可視化する
  • トランザクション（処理単位）をp95レイテンシで順位付けし、スパン（処理の区間）ウォーターフォールで詳細分析できる
  • 構造化ログを6段階の重要度で管理し、アクティブなトレース内のログはトレースと自動リンクされる
  • リリースごとにクラッシュフリーセッション率・ユーザー率を追跡し、アラート（Slack・メール・Webhookなど）を設定できる
  • SQLite（小規模向け）またはPostgreSQL（大規模向け）を選べる単一コンテナ構成で、Dockerだけで起動できる

なぜ注目されているか

SentryのオープンソースセルフホストはRuby/Python製で運用が重かったが、RustとSQLiteを組み合わせた軽量設計により4コアCPUで毎秒5,000イベントを処理できる点が注目されている。Sentry SDKとの互換性を保ちつつAIエージェントのトレース機能まで含む守備範囲の広さも評価されている。

どんな人に役立つか

Sentryの料金やインフラ管理コストを削減したい開発チームや個人開発者に向いている。AIエージェントを本番運用している開発者がデバッグ・パフォーマンス計測ツールを探しているケースにも適している。Dockerさえあれば始められるため、インフラ経験が浅いチームでも導入しやすい。

技術的なポイント

  • Rust製シングルバイナリでAPIサーバーとダッシュボードを兼ね、SQLite（デフォルト）またはPostgreSQLをバックエンドに使う
  • 受信イベントをまずディスクに書いてから200 OKを返す非同期処理設計で、バースト時にも送信元アプリをブロックしない
  • Sentry Spans Protocol v2とOTel（OpenTelemetry）スタイルのスパンを両方サポートし、AIエージェントトレースを取り込む
  • TypeScript製REST APIクライアント（@rustrak/client、MITライセンス）と、AIアシスタント向けのMCPエンドポイントを内蔵する
  • ライセンスはAGPL-3.0（本体）で、匿名使用統計を6時間ごとに送信するがenv変数で無効化できる

試し方

  1. Docker ComposeファイルをリポジトリからダウンロードしてSQLite構成でサーバーを起動する
  2. 既存アプリのSentry DSNをRustrakサーバーのURLに変更する
  3. ブラウザでダッシュボードを開いてエラー・ログ・トレースを確認する
docker compose up -d
