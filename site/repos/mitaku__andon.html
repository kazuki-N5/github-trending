AIエージェントがissueの実装・レビュー・マージを自動化する一人用ソフトウェア工場フレームワーク

何ができるか

  • 「Chief of Staff（参謀）」エージェントがkanban（課題台帳ファイル）からissueを取り出し、ワーカーエージェントに割り当てる。
  • ワーカーエージェントが独立したgit worktreeでコーディングしPRを作成、別モデルのレビュアーエージェントがコードレビューを行う。
  • 「gate（ゲート）」と呼ばれるルール定義により、テストやチェックを通過したPRを人の確認なしに自動マージするかを判定できる。
  • オーナー（人間）への呼び出しは「何を作るか・ユーザー体験・外部への約束・不可逆なリスク・工場自体の変更」の5種類に限定され、それ以外はエージェントが自律処理する。
  • プロジェクト指示・skill・wiki・kanbanをすべてセルリポジトリ（git管理）に置き、別マシンへの移行やバックアップが容易になる。

なぜ注目されているか

AIコーディングエージェントを使った自動開発への関心が高まる中、開発者不在でも複数エージェントが独立して動き続け不在時もPRがマージされるというコンセプトが独自性を持つ。推測 トヨタ生産方式のアンドン灯（監督者を呼ぶ仕組み）をソフトウェア開発に応用した「選択的 Dark Factory」という設計思想が、AI活用と製造哲学を融合したアプローチとして興味を引いていると考えられる。

どんな人に役立つか

すでにターミナルで複数のAIコーディングエージェントを並行稼働させており、自分が離席中もエージェントに作業を続けさせつつマージや不可逆な操作の最終判断は手放したくない一人開発者向け。Linux/WSL環境でDockerを使える人が対象となる。

技術的なポイント

  • CLIツール（`andon`・`kanban`コマンド）をGoで実装しており、エージェントへの指示やkanban（課題台帳ファイル群）の読み書きを担う。
  • Claude Code・OpenAI Codexなど複数のAIモデルをエージェントとして使い、異なるモデルファミリーでレビューを行う設計にしている。
  • Dockerコンテナ（セル）でエージェントの実行環境を信頼境界ごとに隔離し、`FROM`バージョンを上げるPR1本で全セルへAndonの更新が反映される。
  • JSON Schemaでkanbanの形式・ゲートルール・通知などAPIの形式を機械可読な形で定義し、シェルテストで自動検証している。
  • git worktreeを使ってissueごとに独立した作業ブランチを切り、エージェントが複数issueを並行処理できる構成になっている。

試し方

  1. ホストにDockerとbashを用意する（Linux またはWSLが必要）。
  2. `andon init <slug>` でセルリポジトリ（`<slug>-cell`）を作成する。
  3. `cd <slug>-cell && bin/bootstrap` でイメージをビルドしコンテナを起動する。
  4. セル内で `andon create <slug>` でプロジェクトを作成し、`andon open <slug>` でChief of Staffを起動してissueを流す。
andon init <slug> --image ghcr.io/<owner>/andon:<バージョン> --owner <email>
