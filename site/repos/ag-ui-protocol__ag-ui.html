TypeScript 初掲載 2026-11-17（Trendshift 6位） GitHub ↗

AIエージェントとフロントエンドアプリをつなぐオープンプロトコル

何ができるか

  • 双方向イベントストリームでエージェントのトークン生成・ツール呼び出し・状態更新をリアルタイムに配信できる
  • 共有状態をエージェントとアプリの双方から読み書きし、一貫したUIを実現できる
  • 人間が介入して承認・編集・拒否を行うヒューマン・イン・ザ・ループ割り込みに対応している
  • フロントエンドツールをアプリ側で実行し、その結果をエージェントに返すことができる
  • サブエージェントへの委譲と、発生元を明示したイベント属性を持つマルチエージェント構成をサポートしている
  • HTTP+SSE および Protobuf バイナリの2つのトランスポートに対応し、様々な環境で利用できる

なぜ注目されているか

LangChain・CrewAI・Google ADK・Claude Agent SDK など多数のフレームワークがそれぞれ独自のクライアント接続方式を持ち、乱立していた問題を一本化する標準プロトコルとして注目されている。MCP（ツール・コンテキスト）やA2A（エージェント間通信）と並ぶ第三の柱として位置づけられ、エージェントAIのエコシステムを補完する。JSON Schema で仕様が凍結された 1.0 リリースにより、TypeScript・Python・.NET の SDK が自動生成され、後方互換性も確保されている。

どんな人に役立つか

エージェント搭載のウェブ・モバイル・ターミナルアプリを開発するフロントエンド／フルスタックエンジニアに適している。フレームワークやツールのインテグレーション開発者が AG-UI 対応クライアントを横断的にサポートしたい場合にも有用である。

技術的なポイント

  • アプリが RunAgentInput（メッセージ・ツール・共有状態・コンテキスト）を一度送ると、エージェントが型付きイベントのストリームで応答するリクエストモデルを採用している
  • ライフサイクル・テキスト・ツール呼び出し・状態（スナップショットと JSON Patch デルタ）・推論など 31 種類のイベントタイプが定義されている
  • HTTP+SSE と Protobuf バイナリの2種類のトランスポートをサポートし、ミドルウェアで他ソースのイベントを変換できる
  • TypeScript（@ag-ui/client）・Python（ag-ui-protocol）・.NET（AGUI.Client）の公式 SDK に加え、Kotlin・Go・Rust など8言語のコミュニティ SDK がある

試し方

  1. npx create-ag-ui-app@latest でフロントエンドとエージェントフレームワークを選んで新規アプリを作成する
  2. 利用する言語に合わせて SDK をインストールする
  3. FastAPI（Python）などでイベントストリームを返すエージェントサーバーを実装する
  4. TypeScript クライアントからエージェントに接続してストリームを受信する
npx create-ag-ui-app@latest
npm install @ag-ui/client
pip install ag-ui-protocol
dotnet add package AGUI.Client
