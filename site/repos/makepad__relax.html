makepad/relax

Rust 初掲載 2026-11-16（はてなブックマーク 2位） GitHub ↗

rustcなしでRustをJITコンパイル・ライブパッチする実験的処理系

何ができるか

  • rustcやLLVM・リンカなしにCargoパッケージをソースから直接実行できる
  • 関数を初回呼び出し時にコンパイルし、ホット（頻繁に呼ばれる）関数をバックグラウンドで最適化する
  • ファイル保存時に変更した関数を実行中プロセスへライブパッチでき、状態を保ちながら開発できる
  • relax test --liveで保存のたびに影響するテストだけを自動再実行できる
  • relax inspect <pid>でブレークポイント・プロファイリング・メモリリーク検出ツールを使える

なぜ注目されているか

推測 RustのビルドはLLVMを介するため遅く、特に大規模プロジェクトでは開発ループが重い課題とされてきた。RelaxはJITとライブパッチで高速な開発サイクルを実現しようとする点が注目されている。MakepadというRust製UIフレームワークと連携する実用例があることも話題の一因と思われる。

どんな人に役立つか

RustでアプリやUIを開発しており、ビルドや実行の高速化を求めるデベロッパー向け。特にMakepadを使ったUIアプリ開発者に適している。ただし、安全性の保証はRustコンパイラより弱く、リリースビルドはcargo build --releaseで行う前提とされている。

技術的なポイント

  • Rust自身をRustで実装した実験的なJITコンパイラ兼ランタイムで、x64とarm64のネイティブコード生成に対応している
  • コンパイラとコードキャッシュをプログラムの同一プロセス内に持つインプロセス設計をとっている
  • リリースビルドとの速度比較ではx64で1.12倍、arm64で1.24倍程度遅いことがベンチマークで報告されている
  • MakepadのUIフレームワークと統合しており、makepad runコマンドからRelaxが呼び出される

試し方

  1. M4 MacBookでの実測値として、クリーンチェックアウトから大規模3Dゲームの初フレームまで約11秒、2回目以降は1.15秒と報告されている
  2. relax run でCargoパッケージを実行し、ファイル保存で変更が自動パッチされることを確認する
  3. relax test --live でテスト自動再実行を試す
relax run
relax test --live
relax inspect <pid>
