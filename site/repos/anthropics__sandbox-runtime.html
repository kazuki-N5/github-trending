anthropics/sandbox-runtime

TypeScript 初掲載 2026-10-25（Trendshift 16位） GitHub ↗

コンテナ不要でOSレベルのファイル・ネットワーク制限を課す軽量サンドボックスツール

何ができるか

  • CLIツール srt <コマンド> で任意のプロセスをサンドボックス化して実行できる
  • ネットワーク通信はデフォルト全拒否で、許可ドメインリストに登録したドメインだけ通過させる
  • ファイルシステムの書き込みはデフォルト拒否、読み取りはデフォルト許可で、パス単位で細かく制御できる
  • Node.js ライブラリとしてアプリに組み込み、プログラムからサンドボックスを起動できる
  • TLS 終端（通信の復号・再暗号化）機能でリクエストの内容をフィルタリングし、認証情報を動的に注入できる
  • 環境変数やファイルに含まれる認証情報を拒否またはマスクするモードを持つ

なぜ注目されているか

Claude Code 向けに開発されたツールで、AIエージェントやローカルMCPサーバー、bashコマンドなどのサンドボックス化を想定した研究プレビュー版として公開されている。コンテナを使わずmacOS・Linux・Windows それぞれのOS固有の仕組みを使うため、オーバーヘッドが小さく既存の開発フローに組み込みやすい。推測 AIエージェントがローカル環境でコードを実行する用途が増える中、軽量かつ柔軟な隔離手段として注目されていると考えられる。

どんな人に役立つか

AIエージェントや任意コードを実行するツールを開発しており、コンテナを使わずにプロセスを安全に隔離したいエンジニアに役立つ。Claude Code のようなコーディング支援ツールや、ローカルで動くMCPサーバーの開発・運用にも使いどころがある。

技術的なポイント

  • macOS では sandbox-exec（Appleの Seatbelt 機構）向けのプロファイルを動的生成してプロセスのシステムコールを制限する
  • Linux では bubblewrap（非特権サンドボックスツール）でネットワーク名前空間を削除し、seccomp フィルタで Unix ソケットやネストされたユーザー名前空間を禁止する
  • ネットワーク制限は localhost プロキシ（macOS）または Unix ソケット経由のプロキシ（Linux）を介して行い、許可ドメインのみ通過させる
  • Windows（アルファ版）では専用ローカルアカウントへの実行委譲、Windows Filtering Platform によるエグレスフェンス、NTFS ACE による書き込み制限を組み合わせる

試し方

  1. npm でグローバルインストールする
  2. srt <実行したいコマンド> の形でコマンドをサンドボックス化して実行する
  3. ~/.srt-settings.json に allowedDomains などを記述して許可ルールを設定する
npm install -g @anthropic-ai/sandbox-runtime
srt <command>
