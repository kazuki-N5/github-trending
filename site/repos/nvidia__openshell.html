NVIDIA/OpenShell

Rust 初掲載 2026-10-23（Trendshift 13位） GitHub ↗

自律型AIエージェントを権限付きサンドボックスで安全に動かす実行環境

何ができるか

  • 各エージェントを隔離されたサンドボックス（外部から切り離された実行環境）で動かし、アクセスできるファイルやシステムコールを制限できます。
  • すべてのネットワーク接続はサンドボックスを出る前にポリシー（許可ルール）で検査されます。
  • エージェントには本物の認証情報を見せず、承認済みの宛先へのリクエストにだけ OpenShell が認証情報を付け加えます。
  • ポリシー変更を適用する前に形式検証（数学的に性質を確かめる手法）で危険な新しいアクセスを検出し、人間のレビュー待ちにできます。
  • Python、TypeScript、Go、Rust の SDK からゲートウェイに接続でき、Kubernetes には Helm でゲートウェイを配置できます。
  • コーディングエージェント向けのスキルを導入すると、CLI 操作やポリシー作成、ゲートウェイのデバッグをエージェントに任せられます。

なぜ注目されているか

エージェントにファイル操作やパッケージ導入、API 呼び出しをさせつつ、データや秘密情報、ネットワークへの無制限なアクセスは与えないという課題に、カーネルレベルの強制と形式検証で取り組んでいます。NVIDIA が公開しており、リポジトリページでは1万8千を超えるスターを集めています。推測 AIエージェントを業務で動かす際の安全対策への関心の高まりが注目の理由と考えられます。

どんな人に役立つか

AIエージェントに実際のファイルや認証情報を扱わせたいが、アクセス範囲をきちんと制限したい開発者や運用担当者に向いています。複数のエージェントを組織で運用する際のガバナンス（管理の仕組み）づくりにも使えます。

技術的なポイント

  • カーネルを計装（監視用の仕組みを組み込むこと）し、ファイルアクセス、システムコール、ネットワーク接続のたびに実行時にポリシーを強制します。
  • ゲートウェイ（サンドボックス・ポリシー・アクセスを管理する制御面）、スーパーバイザー、サンドボックスの3層で構成されています。
  • サンドボックスは Docker、Podman、またはホストの仮想化機能の上で動き、Linux、Apple Silicon の macOS、WSL 2（実験的）に対応します。
  • ミドルウェア、インターセプター、計算ドライバーを差し込める拡張の仕組みがあります。
  • 匿名のテレメトリを収集しますが、OPENSHELL_TELEMETRY_ENABLED=false で無効化できます。

試し方

  1. Linux、Apple Silicon の macOS、または WSL 2 の Windows に、Docker か Podman を用意します。
  2. インストールスクリプトで CLI とローカルのゲートウェイを導入します。
  3. openshell sandbox create でサンドボックスを作成します（既定のイメージはエージェント未導入の最小構成 Ubuntu です）。
  4. 実際のエージェントを動かすには、ドキュメントの Run Your First Agent に従って OpenCode を動かし、必要に応じて新しいアクセスを承認します。
curl -LsSf https://raw.githubusercontent.com/NVIDIA/OpenShell/main/install.sh | sh
openshell sandbox create --name demo
npx skills add NVIDIA/OpenShell
uv add openshell
