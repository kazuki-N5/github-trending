cloudflare/security-audit-skill

GitHub Trending 2位★ +1,712JavaScriptGitHub ↗

コーディングエージェントを多段階のセキュリティ監査役に変えるスキル

何ができるか

  • 偵察・網羅的な脆弱性探し・候補の検証・構造化出力・記録の独立検証・レポート作成という6つのフェーズで監査を進めます。
  • 偵察フェーズでアーキテクチャや信頼境界（権限や信頼度が変わる境目）、入力箇所を調べ、architecture.mdとcoverage-ledger.json（どこを調べたかの台帳）にまとめます。
  • 見つかった脆弱性の候補は、発見したエージェントとは別の新しいエージェントが反証を試みて検証します。
  • 結果をconfirmed（確認済み）、needs_validation（未確定の事実が残る）、rejected（反証済み）の3種類に分けてfindings.jsonに書き出し、report-schema.jsonで形式をチェックします。
  • 検証済みの記録からREPORT.md、FINDINGS-DETAIL.md、NEEDS-VALIDATION.mdといった報告書を作ります。
  • 同じリポジトリへの複数回の実行は積み重ねられ、前回の台帳や結果を使って未調査の部分や変更されたコードを重点的に調べます。

なぜ注目されているか

Cloudflareが社内の脆弱性発見ハーネス（自動で脆弱性を探す仕組み）の出発点となったスキルとして公開しており、ブログ記事「Build your own vulnerability harness」でも紹介されています。推測 AIエージェントによるコード監査への関心が高まるなか、大手企業が実際に使った手法をそのまま試せる点が注目を集めていると考えられます。

どんな人に役立つか

コーディングエージェントを使って自分のコードベースのセキュリティを点検したい開発者に向いています。セキュリティ監査の進め方や、AIの誤検知を減らす検証の仕組みを学びたい人にも参考になります。

技術的なポイント

  • スキルはMarkdownの指示書（SKILL.mdや各フェーズ用のファイル）で構成され、Webの認証、クライアント側、サプライチェーン、クラウド、メモリ安全性、LLMなど分野別の攻撃パターン集を持ちます。
  • 互いに独立したサブエージェント（親エージェントから並列に起動される別のエージェント）を使い分け、見つける役と確かめる役を必ず分けます。
  • 依存ライブラリなしのNode.jsスクリプトvalidate-findings.cjsとvalidate-coverage-ledger.cjsで、結果ファイルと台帳の形式を検証します。
  • 対象コードのビルドやテストを実行する場合は、外部ネットワーク遮断や書き込み先制限などを備えたOSレベルのサンドボックス（隔離環境）が必要で、ない場合はコードを実行せずneeds_validationとして残します。

試し方

  1. ツール呼び出しと並列サブエージェントに対応したコーディングエージェントと、Node.jsを用意します。
  2. Skills CLIでスキルをインストールします（ユーザー全体に入れる場合は--globalを付けます）。
  3. 監査したいコードベースでエージェントを起動し、「security audit this codebase」のように依頼するとスキルが自動で起動します。
  4. 出力先を指定しない場合、結果は~/security-audit-skill/<リポジトリ名>/run-<N>に保存されます。
npx skills add https://github.com/cloudflare/security-audit-skill --skill security-audit
npx skills add https://github.com/cloudflare/security-audit-skill --skill security-audit --global
npx skills --help

Graphify-Labs/graphify

GitHub Trending 7位★ +802PythonGitHub ↗

コードや資料を丸ごと検索できる知識グラフに変えるAIアシスタント用スキル

何ができるか

  • AIコーディングアシスタントで「/graphify .」と入力すると、コード・ドキュメント・PDF・画像・動画を含むプロジェクト全体を知識グラフ（概念をノード、関係を辺で表したデータ）にまとめます。
  • 結果として、ブラウザでクリック・絞り込み・検索ができるgraph.html、要点をまとめたGRAPH_REPORT.md、グラフ全体を保存したgraph.jsonの3ファイルを出力します。
  • 「graphify query」で自然文の質問に関係する部分グラフを返し、「graphify path A B」で2つの要素のつながりをたどり、「graphify explain」で1つの概念の接続を説明します。
  • 最もつながりの多い概念（God nodes）の抽出や、Leiden法（グラフを密につながったまとまりに分ける手法）によるサブシステムへの分割を行います。
  • 約40言語で関数呼び出し・import・継承などのファイル間の関係を解決し、「# NOTE:」「# WHY:」コメントやADR/RFCの引用もコードに結び付いたノードにします。
  • Claude Code、Cursor、Codex、Gemini CLI、GitHub Copilotなど20以上のアシスタントに対応し、「graphify install」で使っているアシスタントを検出してスキルを登録します。

なぜ注目されているか

ファイルをgrepで探す代わりにグラフを問い合わせることでAIエージェントの作業を効率化できる点が特徴で、README ではベンチマーク（LOCOMOでrecall@10が0.497、グラフ構築のLLMクレジット0）も示されています。コードの解析はLLMを使わずローカルで決定的に行い、ベクトルストア（埋め込みベクトルの検索用データベース）も使わないという方針が打ち出されています。推測 Claude CodeやCodexなどのエージェント型ツールの普及で、大きなコードベースを少ないトークンで理解させる手段への関心が高まっていることも注目の理由と考えられます。

どんな人に役立つか

Claude CodeやCursorなどのAIコーディングアシスタントで、大きなコードベースや資料を効率よく把握させたい開発者に役立ちます。初めて触るプロジェクトの全体構造や、要素同士のつながりを把握したいときにも使えます。

技術的なポイント

  • コードはtree-sitter（多言語対応の構文解析ライブラリ）でAST（抽象構文木）に解析し、LLMを使わず手元のマシンだけで決定的に処理します。
  • ドキュメント・PDF・画像・動画は、アシスタントのモデルや設定したAPIキー（OpenAI、Gemini、Claude、Ollamaなど）を使った意味解析で同じグラフに取り込みます。
  • 各辺には、ソースに明示されていた関係を表すEXTRACTEDか、graphifyが推論で解決した関係を表すINFERREDのタグが付きます。
  • 埋め込みやベクトルストアは使わず、実際にたどれるグラフとしてgraph.jsonに保存し、互換性確認用にschema_versionとgraphify_versionを記録します。
  • PDF・Office・SQLスキーマ・PostgreSQL・MCPサーバー・Neo4jへの出力などは、必要なものだけ追加でインストールするオプション（extras）として提供されています。

試し方

  1. Python 3.10以上とuv（またはpipx）を用意します。
  2. PyPIのgraphifyy（yが2つ）パッケージをインストールし、「graphify install」で使っているアシスタントにスキルを登録します。
  3. AIアシスタントを開いて「/graphify .」と入力します（Codexでは「$graphify」を使います）。
  4. graphify-outフォルダに出力されたgraph.htmlをブラウザで開いたり、graphify query・path・explainコマンドでグラフに質問したりします。
uv tool install graphifyy
pipx install graphifyy
graphify install
/graphify .
graphify explain "APIRouter"
graphify path "FastAPI" "ModelField"
graphify install --project

Redditのスレッドから生まれ、汎用的な「開発者として振る舞って」というプロンプトではなく、専門性・個性・成果物まで作り込んだエージェント集として育ってきたことがREADMEで紹介されています。推測 Claude CodeやCodexなどAIコーディングツールのサブエージェント（特定の役割を任せる補助AI）機能が広まり、すぐ使える高品質な役割定義の需要が高まっていることが注目の理由と考えられます。

どんな人に役立つか

  • 各エージェントは、名前・説明・色を書いたフロントマター（ファイル先頭のメタデータ）付きのMarkdownファイルとして定義されています。

  4. Claude Codeのセッションで「Frontend Developerモードを有効にしてReactコンポーネントを作って」のようにエージェントを指名して使います。

cp engineering/*.md ~/.claude/agents/
./scripts/convert.sh
./scripts/install.sh
./scripts/install.sh --tool claude-code --division engineering,security
./scripts/install.sh --list teams

anthropics/knowledge-work-plugins

GitHub Trending 11位★ +267PythonGitHub ↗

Claudeを営業・法務・財務など職種別の専門アシスタントにするプラグイン集

何ができるか

  • 営業、カスタマーサポート、プロダクトマネジメント、マーケティング、法務、財務、データ分析、社内検索、バイオ研究、生産性向上など、職種ごとのプラグイン11種類を公開しています。
  • 各プラグインはスキル、コネクタ、スラッシュコマンド、サブエージェントをひとまとめにしており、その職種の仕事を手伝うための出発点になります。
  • スキル（その分野の知識や手順を書いたファイル）は、関係する場面でClaudeが自動的に参照します。
  • 「/sales:call-prep」や「/data:write-query」のようなスラッシュコマンドで、決まった作業を明示的に実行できます。
  • Slack、Notion、Jira、HubSpot、Snowflake、PubMedなどの外部ツールとコネクタでつなぎ、データを取り込みながら作業できます。
  • cowork-plugin-managementプラグインを使うと、自社の道具や業務の流れに合わせて新しいプラグインを作ったり既存のものを手直ししたりできます。

なぜ注目されているか

AnthropicがClaude Cowork向けに、自社の業務で作ったり参考にしたりしたプラグインをオープンソースとして公開したものです。推測 プログラムを書かずにMarkdownとJSONだけでClaudeを職種別の専門家に仕立てられる手軽さが、エンジニア以外の知識労働者にも使える仕組みとして注目されていると考えられます。

どんな人に役立つか

Claude CoworkやClaude Codeを使っていて、営業・法務・財務・データ分析などの定型業務をAIに任せたい人やチームに役立ちます。自社の用語や業務手順をClaudeに覚えさせたい管理者や、プラグインの作り方を学びたい人の参考にもなります。

技術的なポイント

  • 各プラグインは、マニフェスト（.claude-plugin/plugin.json）、ツール接続設定（.mcp.json）、commandsフォルダ、skillsフォルダという共通の構成になっています。
  • 外部ツールとの接続にはMCPサーバー（Model Context Protocol: AIと外部ツールをつなぐための共通規格に沿ったサーバー）を使います。
  • すべての部品がMarkdownとJSONのファイルだけでできていて、コードもインフラもビルド手順も要りません。
  • .mcp.jsonを書き換えて接続先を差し替えたり、スキルのファイルに社内の用語や手順を書き足したりしてカスタマイズできます。

試し方

  1. Claude Coworkを使う場合は、claude.com/pluginsからプラグインをインストールします。
  2. Claude Codeを使う場合は、まずこのリポジトリをマーケットプレイスとして追加し、続けて使いたいプラグイン（例: sales）をインストールします。
  3. インストールするとプラグインは自動で有効になり、スキルは関係する場面で使われ、/sales:call-prepのようなスラッシュコマンドもセッション内で使えるようになります。
claude plugin marketplace add anthropics/knowledge-work-plugins
claude plugin install sales@knowledge-work-plugins

何ができるか

  • Claude Code、OpenAI Codex CLI、Cursor、OpenCode、Antigravity CLI、GitHub Copilot、Piの7種類のAIコーディングツール（README では「ハーネス」と呼ぶ）で同じプラグイン群を使えます。

  • Claude CodeやCodex CLIではマーケットプレイス（プラグインの配布元）として登録し、コマンド1つでプラグインを追加できます。
