プロキシ・トンネル・VPNの仕組みとGFW（中国のネット検閲システム）の回避手法を解説した中国語のオープン教科書

何ができるか

  • プロキシ・トンネル・VPNの動作原理を詳細に解説している

  • git経由でのプロキシ設定やmacOSターミナルのプロキシ設定方法も収録している
  • 証明書エラーの対処法（サードパーティDNSへの切り替えなど）も含む実践的なトラブルシュート手順を提供している

なぜ注目されているか

どんな人に役立つか

  • DNSキャッシュポイズニングやSSL遮断といったGFWの具体的な攻撃手法を技術原理レベルで記述している
  • Shellスクリプトを使ったプロキシ設定や環境構築の自動化手順を含む

試し方

D4Vinci/Scrapling

Trendshift 12位PythonGitHub ↗

HTTPリクエストからフルクロールまで対応するPython製Webスクレイピングフレームワーク

何ができるか

  • CSSセレクタ・XPath・正規表現でHTML要素を抽出でき、サイト変更後も要素を追跡する適応型セレクタ機能を持つ。
  • CloudflareのTurnstileやInterstitialを回避しつつJavaScriptをレンダリングするブラウザ自動操作に対応する。
  • Scrapy風のスパイダーAPIで並行クロールが可能で、per-domainスロットリングやpause/resume機能も備える。
  • JSON・JSONL・CSV・XMLへのエクスポートが標準装備されており、コマンドライン(CLI)からも利用できる。
  • AIエージェント向けのMCPサーバーや、インタラクティブシェル、RAGパイプラインへの組み込みをサポートする。

なぜ注目されているか

Webスクレイピングに必要な機能（HTTPリクエスト、ブラウザ操作、パース、クロール）を1ライブラリで統合している点が注目される。プロジェクト公表のベンチマークでは5000要素のパースがBeautifulSoup比で約780倍高速とされており、大規模用途での性能が評価されている。推測 AI・RAG向けのMCPサーバー統合が、LLMエージェントによるWebデータ取得需要の増加と合致し、注目を集めていると考えられる。

どんな人に役立つか

Pythonで中規模から大規模のスクレイピングを行うエンジニアや、Cloudflare等のボット対策を持つサイトからデータ収集が必要な開発者に適する。AIエージェントやRAGパイプライン（検索強化生成：LLMにリアルタイムのWeb情報を与える仕組み）を構築するチームにも活用できる。

技術的なポイント

  • Python 3.10以上が必要で、ブラウザ操作にはPlaywright（Chromiumまたは Chrome）を使用し、CDP経由でリモートブラウザにも接続できる。
  • TLS指紋偽装やブラウザヘッダーの模倣により、一般的なボット検出を回避するHTTPフェッチャーを搭載する。
  • サイト構造変更後も要素を再発見する適応型トラッキング機能を、パーサーレベルで実装している。
  • AIエージェントとの連携用にMCP（Model Context Protocol）サーバーを内蔵しており、`pip install 'scrapling[ai]'`で有効化できる。

試し方

  1. pipでscraplingをインストールする。
  2. ブラウザ操作が必要な場合は`scrapling[fetchers]`オプションを追加してインストールし、`scrapling install`でPlaywrightを初期化する。
  3. Pythonスクリプト内でFetcherをインポートし、URLを取得してCSSセレクタで要素を抽出する。
  4. CLIを使う場合は`scrapling extract get <URL> <出力ファイル>`コマンドで直接抽出できる。
pip install scrapling
pip install "scrapling[fetchers]"
scrapling install
docker pull pyd4vinci/scrapling
scrapling extract get 'https://quotes.toscrape.com/' quotes.md

Trendshift 13位JavaScriptGitHub ↗

コードベースをインタラクティブな平易な英語マップに変換するClaude Codeプラグイン

何ができるか

  • アプリ全体からファイル単体まで多段階でズームできるインタラクティブマップを生成する
  • フロントエンドのリクエストとバックエンドのエンドポイントを別リポジトリをまたいで対応付ける
  • マップに自然言語で質問でき、関連コードの流れをミニマップで答えてくれる
  • 公開鍵・オープンなDBテーブル・認証なしエンドポイントなどAIが生成しがちなセキュリティ問題を検出し修正案を示す
  • AIアシスタントが直近で変更した箇所とその理由をハイライト表示する
  • PRDや仕様書からコードが存在しない段階でも計画用マップを作れるBlueprintsモードがある

なぜ注目されているか

推測 AIコーディングツールの普及でAI生成コードの量が増え、全体像を把握しにくいという課題が顕在化している。コード検索やドキュメント生成とは異なり、ファイル間・リポジトリ間の接続を視覚的に示す点が差別化になっている。依存関係ゼロ・完全ローカル動作というプライバシー重視の設計も注目を集める要因と考えられる。

どんな人に役立つか

AIアシスタントで素早くアプリを作った後に「全体がどうつながっているか」を把握したい開発者に向いている。フロントエンドとバックエンドが別リポジトリに分かれているプロジェクトや、セキュリティチェックを手軽に行いたいチームにも役立つ。

技術的なポイント

  • Claude CodeまたはOpenAI Codexのプラグインとして動作し、LLMにコードベースを読み込ませてマップを生成する
  • スキャン・マップ生成・ローカルサーバーはすべてユーザーのマシン上で実行され、外部への通信は任意のメール登録のみ
  • 依存パッケージゼロで動作し、マップをgit管理外の`floorplan/`フォルダに出力する
  • 結果を単一のHTMLファイルとしてエクスポートして共有できる

試し方

  1. Node.js 18以上がインストールされていることを確認する
  2. Claude Codeを使っている場合は以下のコマンドでプラグインを追加する
  3. Codexを使っている場合はアプリ内のMarketplace、またはターミナルから追加する
claude plugin marketplace add haydenschmitty/floorplan

  • 秦の始皇帝・張騫・蘇軾など著名人物の生涯をマップ上のルートとして再生できる人物年代記機能を備える。
  • LLM/AIエージェントがyear・placeの2パラメータだけでURLを生成でき、座標を意識せずに地図を操作できる。
  • 古代地名クイズ（Map Pinpoint Challenge）で中国史の地理知識を楽しく試せる。

なぜ注目されているか

推測 中国の歴史書や漢詩を読む際に「どこの地名か」を現代地図上で確認したいというニーズは大きく、18王朝・2400年分を一枚の地図で行き来できる手軽さが人気を集めている。AI連携APIを標準装備しており、LLMの歴史地理可視化ツールとしても活用できる点が開発者層に注目されている。

どんな人に役立つか

中国史・漢詩・古典文学に興味がある歴史ファンや学生向け。LLMエージェントの地理可視化バックエンドとして組み込みたい開発者にも適している。

技術的なポイント

  • 依存ライブラリなし・ビルドステップなしの静的HTMLで動作し、任意の静的ファイルサーバーから配信できる。
  • GISデータは谭其骧『中国歴史地図集』・CHGIS（ハーバード燕京研究所）・Hartwell歴史GISデータセットに基づく。
  • 古今地名解決・行政区画変遷データを内包し、古代名と現代名の双方向解決ができる。
  • browser automation（Playwright/WebMCP）用のwindow.atlasAPI、CLI向けPythonスクリプトも提供している。

試し方

  1. リポジトリをクローンする。
  2. 任意の静的HTTPサーバーで配信し、ブラウザで開く。

cd jiangshan-map
python3 -m http.server 8000

nishikawaakira/waf-dojo

はてなブックマーク 1位39 usersGoGitHub ↗

AWS WAFの防御ルールをゲーム感覚で実践的に学べるハンズオン道場

何ができるか

  • SQLインジェクションやXSS、レート制限など6種のチュートリアルで段階的にAWS WAFの基礎を学べる
  • チュートリアル修了後に解放されるゲームモードでは、攻撃概要だけを渡されて自力でWAFルールを設計する6ステージに挑戦できる
  • 41件の脆弱性ラボと2件のログ分析オペドリルで、実際の攻撃パターンに対するルール作成を繰り返し練習できる
  • 攻撃ブロック率と誤検知率を組み合わせたスコアリングで、ルールの精度を数値で確認できる
  • 管理者がコンテストモードを有効化すると、時間制限付きの問題セットを複数プレイヤーで競うことができる
  • uTLSでブラウザやツールのTLSフィンガープリントを再現したトラフィックジェネレータが自動的に攻撃と正常リクエストを送信する

なぜ注目されているか

推測 AWS WAFは設定の自由度が高い一方で、実際に攻撃を受けて試行錯誤できる環境を個人で用意するのは難しい。本リポジトリはその環境をTerraform一発で構築し、ゲームのスコアで達成度を可視化することで学習継続のモチベーションを維持しやすい点が注目されている。推測 JA4フィンガープリントやBot検出といった最新トピックも含む幅広いカバレッジも評価されていると考えられる。

どんな人に役立つか

AWS WAFの設定を実務で担当するインフラ・セキュリティエンジニアや、社内セキュリティ研修のコンテンツを探しているトレーナーに役立つ。個人学習・学校教育・社内研修は無償で利用でき、AWS環境さえあれば手軽にデプロイして試せる。

技術的なポイント

  • バックエンドはGo 1.26以上で実装されたAWS Lambda関数URLで動作し、プレイヤーごとにALB・Web ACL・DynamoDBリソースをTerraform 1.6以上で払い出す
  • ダミーショップアプリはすべてのリクエストに200を返すため、4xxレスポンスはWAFによるブロックと明確に判別できる
  • トラフィックジェネレータがuTLSライブラリを使ってブラウザや攻撃ツールのTLSフィンガープリント（JA4）を再現した攻撃リクエストを生成する
  • オプションでCloudFrontを前段に配置することでCloudFront向けWAFルールの学習も可能

試し方

  1. Go 1.26以上、Terraform 1.6以上、および管理者相当のAWS認証情報を用意する
  2. aws sts get-caller-identityでデプロイ先のAWSアカウントを確認する
  3. terraform/terraform.tfvars.exampleをterraform/terraform.tfvarsにコピーしてplayer_countなどを編集する
  4. make deployでLambdaのビルドとTerraformのapplyを一括実行する
  5. terraform -chdir=terraform output -json player_accessで各プレイヤーのゲームURLとAWSコンソールURLを取得し、それぞれに配布する
  6. 終了後はmake destroyで環境を削除する
aws sts get-caller-identity
cp terraform/terraform.tfvars.example terraform/terraform.tfvars
make deploy
terraform -chdir=terraform output -json player_access
make dev
make destroy
