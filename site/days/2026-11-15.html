RoutineMiku/apkstart

Trendshift 2位JavaScriptGitHub ↗

WindowsでAPKをダブルクリックするだけでAndroidアプリをネイティブ風に起動できるランチャー

何ができるか

  • APKファイルをダブルクリックするだけでインストールし、デスクトップアイコンとスタートメニューのショートカットを自動作成できる
  • 各AndroidアプリがWindowsの独立したウィンドウで起動し、タイトルバーやウィンドウサイズがアプリごとに記憶される
  • フルスクリーンとウィンドウモードの両方をサポートし、Windows上でネイティブアプリに近い体験を提供する
  • ユーザーフォルダ（%USERPROFILE%\ApkStartShared）とエミュレータ間でファイルを双方向に同期できる共有フォルダ機能がある
  • 内蔵のアップデート確認機能により、最速のダウンロードソースから自動的に更新できる
  • コマンドラインからAPKのインストール（ApkStart.exe <file.apk>）やアプリの起動（--launchオプション）が可能

なぜ注目されているか

推測 WindowsでAndroidアプリをネイティブアプリのように実行できるシンプルさが評価されている。APKのダブルクリックという直感的な操作でインストールから実行まで完結できる点と、QEMUベースの自己完結型ランタイムを同梱している点が他のソリューションと差別化されている。

どんな人に役立つか

Windows環境でAndroidアプリを手軽に動かしたい開発者やユーザー向け。特にAndroidアプリのデバッグ・テストをWindowsで行いたい開発者や、特定のAndroidアプリをPCで利用したいユーザーに適している。ARM専用アプリの実行にも対応する互換モードを備えている。

技術的なポイント

  • QEMU仮想化技術とAndroid 14システムイメージを使用してAndroid実行環境を提供する
  • adbとAndroid Emulatorを組み合わせてAPKの管理・インストール・実行を制御する
  • シェル部分はサードパーティ依存なしで構築されており、AOSP・QEMU・adbの上に直接構築されている
  • Node.js（npm）ベースのビルドシステムを採用し、フルインストーラー（約1.3GB）とポータブルZIP（95MB）の2種類のビルドを提供する
  • ハードウェアアクセラレーション（オプション）をサポートし、既存エミュレータのadbポートの再利用も可能

試し方

  1. GitHubからインストーラー（約1.3GB、ランタイム同梱）またはポータブルZIP（95MB、初回起動時にランタイムをダウンロード）を入手する
  2. インストーラーの場合は実行してセットアップを完了する。ポータブルの場合はZIPを任意のフォルダに展開する
  3. インストールしたいAPKファイルをダブルクリックしてアプリをインストールする
  4. 作成されたデスクトップアイコンまたはスタートメニューのショートカットからアプリを起動する
  5. ソースからビルドする場合はnpm installの後、npm startで開発モード起動、npm run packでポータブルビルド、npm run build:exeでインストーラーを作成する
npm install
npm start
npm run pack
npm run build:exe
ApkStart.exe <file.apk>
ApkStart.exe --launch <package>

libracoder/kiri

Trendshift 3位RustGitHub ↗

macOS・Windows・Linux向けの小さく高速なコンテナランタイム

何ができるか

  • Docker Engine APIを実装しており、既存のdocker CLIやComposeがそのまま使える
  • コンテナの起動・終了がAPIレベルで約2.5msと非常に高速
  • デーモンのメモリ使用量が約15MBと軽量で、60秒アイドル後にVMがスリープする
  • http://<name>.kiri.local でローカルドメインとHTTPSを自動提供する
  • ワンコマンドでシングルノードのKubernetesクラスターを起動できる
  • OrbStackやDocker Desktopからのイメージ・ボリューム・コンテナ移行をサポートする

なぜ注目されているか

推測 Docker DesktopやOrbStackの代替として、起動速度とリソース効率を大幅に改善した点が注目を集めている。ベンチマークではDocker Desktopの約85倍高速とされており、開発体験の向上に直結する。Rustで実装された独自のVM・ゲストエージェント構成が技術的な新鮮さを持つ。

どんな人に役立つか

Docker互換のコンテナ環境を軽量・高速に使いたい開発者に向いている。特にmacOSやWindowsでDocker DesktopやOrbStackの重さやコストに不満を感じているエンジニアに適している。既存のDockerワークフローをそのまま維持しながら乗り換えたい人にも有用。

技術的なポイント

  • RustでDocker Engine APIを実装し、既存Dockerクライアントとの互換性を確保している
  • ホストデーモンとゲスト間の通信にvsockを使用し、カスタム約10MBのLinuxカーネルをVMとして利用している
  • ゲストエージェントは約900KBのRustプログラムがPID 1として動作し、clone3で直接コンテナを起動している
  • runc・containerd shim・dockerdを使わずシンプルな構成を実現している
  • 38言語対応のネイティブUIを備え、メニューバーアイコンからも操作できる

試し方

  1. runkiri.com/releases からプラットフォームに合ったパッケージ（.dmg / .msi / .deb / .rpm）をダウンロードしてインストールする
  2. 初回起動時にkiriというDockerコンテキストが自動作成される
  3. docker --context kiri コマンドでKiriを使ってコンテナを実行する
docker --context kiri run --rm alpine echo hello
docker --context kiri compose up -d
kiri k8s start
kiri machine create dev --distro ubuntu && kiri machine shell dev
kiri import

deepseek-ai/chat-demo

Trendshift 4位TypeScriptGitHub ↗

バックエンド不要のDeepSeek API対応静的チャットWebアプリ

何ができるか

  • 複数会話の管理（自動タイトル付け、改名、削除）とメッセージ分岐切り替えができる
  • ストリーミング応答、ディープシンク、スマート検索、リンク読み取りとソース引用に対応する
  • ファイルのアップロード・ペースト・ドラッグ＆ドロップ、音声入力、読み上げ再生が使える
  • Markdown、シンタックスハイライト、KaTeX数式、Mermaidダイアグラムをレンダリングできる
  • 会話履歴をZIPアーカイブとしてインポート／エクスポートできる
  • 日本語・英語・中国語（簡体字）対応、ライト／ダークテーマ、モバイルレイアウトをサポートする

なぜ注目されているか

アプリケーションサーバーが不要で、静的ファイルとして任意のホスティングサービスやローカルで動作するため手軽に試せる点が注目されている。APIキーや設定はブラウザのlocalStorageに保存されるため、サーバー側にデータを送らずに済む設計も評価されている。DeepSeek公式のデモ実装として、機能が豊富でリファレンス実装としても参考になる。

どんな人に役立つか

DeepSeek APIを使ったチャットUIをすぐに試したい開発者や、カスタマイズ可能なフロントエンドを探しているエンジニアに向いている。バックエンドを用意せずに静的サイトとして公開したい場合にも適している。

技術的なポイント

  • ブラウザからDeepSeek API（Anthropic互換のMessages/Files API）に直接接続し、バックエンド不要で動作する
  • RspackとTypeScriptでビルドされ、oxlint・oxfmtによる静的解析とフォーマットを採用している
  • 会話データと添付ファイルはIndexedDB、APIキーと設定はlocalStorageにブラウザ内で保存される
  • ASR/TTS音声エンドポイントを利用した音声入力・読み上げ機能を実装している

試し方

  1. Node.js 22.12以上とpnpmをインストールする
  2. リポジトリをクローンしてpnpm installを実行する
  3. pnpm devを実行してhttp://localhost:8090を開く
  4. 設定画面でDeepSeek APIキーを入力してチャットを開始する
pnpm install
pnpm dev
pnpm build

AIコーディングエージェントがライブChromeブラウザを操作・検査できるMCPサーバー

何ができるか

  • Puppeteerを使ってChromeブラウザを操作し、ページナビゲーションやクリックなどを自動実行できる
  • パフォーマンストレースを記録し、Chrome DevToolsを通じてインサイトを抽出できる
  • ネットワークリクエストの解析、スクリーンショット撮影、コンソールメッセージの確認が可能
  • ソースマップ付きスタックトレースによりデバッグ情報を正確に取得できる
  • アクセシビリティ監査・LCP最適化・メモリリーク調査などのスキルが組み込まれている

なぜ注目されているか

AIコーディングエージェントがブラウザを直接操作・検査できるツールへの需要が高まっており、MCP対応によりClaude・Cursor・Copilotなど主要エージェントから利用しやすい点が注目されている。推測 ChromeDevToolsチームが公式に開発しているため、信頼性と将来的なメンテナンスへの期待も高い。

どんな人に役立つか

AIコーディングアシスタントを使って開発するエンジニアや、ブラウザ操作を含むエージェントワークフローを構築したいチームに適している。フロントエンドのパフォーマンス改善やデバッグ作業をAIエージェントに任せたい開発者にも有用。

技術的なポイント

  • PuppeteerによりChromeブラウザを制御し、信頼性の高いブラウザ自動化を実現している
  • Chrome DevToolsフロントエンドと統合し、パフォーマンストレースやデバッグ情報を取得する
  • CrUX（Chrome UX Report）APIを用いてフィールドパフォーマンスデータを補完できる

試し方

  1. Node.js LTSと最新安定版のChromeをインストールする
  2. MCPクライアントの設定に `npx -y chrome-devtools-mcp@latest` のエントリを追加する
  3. CLIとして使う場合は npm でグローバルインストールし、コマンドを実行する
npm i chrome-devtools-mcp@latest -g
chrome-devtools navigate_page 1 --url "https://example.com"
chrome-devtools take_screenshot 1 --filePath /tmp/screenshot.png
chrome-devtools stop
