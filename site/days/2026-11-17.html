hitkeeen/blender-ai-mcp-addon

Trendshift 3位PythonGitHub ↗

BlenderにAIチャットとMCPサーバーを統合し、3Dシーン操作を自動化するアドオン

何ができるか

  • AIがシーンの検査・オブジェクト作成・編集・マテリアル管理など21種のツールをBlender上で直接実行できる。
  • ChatGPT（OpenAI）、Claude（Anthropic）、Gemini、Ollama など複数のAIプロバイダーを切り替えて利用できる。
  • マネージャー・ワーカー・レビュアーの役割分担によるマルチエージェントのチームチェーンで大規模タスクを自動化できる。
  • Poly Haven、Sketchfab、Poly Pizza からアセットを検索してBlenderに直接インポートできる。
  • 操作ごとに承認要求を設定したり実行中のタスクをキャンセルしたりする制御機能を備える。
  • Blenderのサイドバーに組み込まれたチャットワークスペース「Studio」でAIと対話できる。

なぜ注目されているか

BlenderにMCPサーバーを直接組み込み、AIが3Dシーンを自律的に操作できる点が従来のスクリプト補助ツールとは一線を画す。複数のAIプロバイダーへの対応とマルチエージェントワークフローにより、複雑な3D制作タスクの自動化が現実的になっている。

どんな人に役立つか

AIを活用して3Dモデリングや素材管理・アセット配置の作業を効率化したいBlenderユーザーに適している。Pythonスクリプトを使ったプロシージャルな制作フローやワークフロー自動化を試みたいデベロッパーにも役立つ。

技術的なポイント

  • MCP（Model Context Protocol）サーバーをBlenderアドオン内部に実装し、外部AIツールからBlenderを直接操作できる仕組みを実現している。
  • シーン検査・オブジェクト生成・編集・ビューポートスクリーンショット・スクリプト実行・Blender API検索・エクスポートの7グループ計21ツールを提供する。
  • チームチェーン機能でマネージャーが計画を立て、ワーカーが実行し、レビュアーが検証するマルチエージェント構成をサポートする。
  • Python検証レイヤーで不正なBlender API操作をブロックし、ミューテーション操作には名前付きアンドゥステップが記録される。

試し方

  1. Blender 4.2以降をインストールする。
  2. GitHubのReleasesページからZIPファイルをダウンロードする。
  3. Blenderの拡張設定（Edit > Preferences > Extensions）でZIPをディスクからインストールする。
  4. 3DビューポートのサイドバーでMCP Proパネルを開く。
  5. 使用するAIプロバイダー（OpenAI、Claude、Gemini等）の接続情報を設定する。

ag-ui-protocol/ag-ui

Trendshift 6位TypeScriptGitHub ↗

AIエージェントとフロントエンドアプリをつなぐオープンプロトコル

何ができるか

  • 双方向イベントストリームでエージェントのトークン生成・ツール呼び出し・状態更新をリアルタイムに配信できる
  • 共有状態をエージェントとアプリの双方から読み書きし、一貫したUIを実現できる
  • 人間が介入して承認・編集・拒否を行うヒューマン・イン・ザ・ループ割り込みに対応している
  • フロントエンドツールをアプリ側で実行し、その結果をエージェントに返すことができる
  • サブエージェントへの委譲と、発生元を明示したイベント属性を持つマルチエージェント構成をサポートしている
  • HTTP+SSE および Protobuf バイナリの2つのトランスポートに対応し、様々な環境で利用できる

なぜ注目されているか

LangChain・CrewAI・Google ADK・Claude Agent SDK など多数のフレームワークがそれぞれ独自のクライアント接続方式を持ち、乱立していた問題を一本化する標準プロトコルとして注目されている。MCP（ツール・コンテキスト）やA2A（エージェント間通信）と並ぶ第三の柱として位置づけられ、エージェントAIのエコシステムを補完する。JSON Schema で仕様が凍結された 1.0 リリースにより、TypeScript・Python・.NET の SDK が自動生成され、後方互換性も確保されている。

どんな人に役立つか

エージェント搭載のウェブ・モバイル・ターミナルアプリを開発するフロントエンド／フルスタックエンジニアに適している。フレームワークやツールのインテグレーション開発者が AG-UI 対応クライアントを横断的にサポートしたい場合にも有用である。

技術的なポイント

  • アプリが RunAgentInput（メッセージ・ツール・共有状態・コンテキスト）を一度送ると、エージェントが型付きイベントのストリームで応答するリクエストモデルを採用している
  • ライフサイクル・テキスト・ツール呼び出し・状態（スナップショットと JSON Patch デルタ）・推論など 31 種類のイベントタイプが定義されている
  • HTTP+SSE と Protobuf バイナリの2種類のトランスポートをサポートし、ミドルウェアで他ソースのイベントを変換できる
  • TypeScript（@ag-ui/client）・Python（ag-ui-protocol）・.NET（AGUI.Client）の公式 SDK に加え、Kotlin・Go・Rust など8言語のコミュニティ SDK がある

試し方

  1. npx create-ag-ui-app@latest でフロントエンドとエージェントフレームワークを選んで新規アプリを作成する
  2. 利用する言語に合わせて SDK をインストールする
  3. FastAPI（Python）などでイベントストリームを返すエージェントサーバーを実装する
  4. TypeScript クライアントからエージェントに接続してストリームを受信する
npx create-ag-ui-app@latest
npm install @ag-ui/client
pip install ag-ui-protocol
dotnet add package AGUI.Client

NVIDIA/SkillEvaluator

Trendshift 7位PythonGitHub ↗

AIエージェントスキルの品質・重複・実動作を3段階で自動評価するフレームワーク

何ができるか

  • スキルの安全性・整合性・ハーネス互換性を検証するTier1バリデーション機能を備える
  • 埋め込みモデルを使ってスキル間の意味的重複や類似ガイダンスを検出するTier2重複排除を行う
  • DockerサンドボックスでエージェントにスキルをON/OFFさせてTier3ライブ評価を実施する
  • 評価用データセットを自動生成するオートパイロット機能で評価ソースを作成できる
  • GitHubおよびGitLabのCI/CDパイプラインへ組み込むためのCI設定テンプレートを提供する
  • Claude CodeやCodexなどのエージェントにスキルとして直接インストールして評価依頼ができる

なぜ注目されているか

AIエージェント向けスキルの品質保証は標準化が難しかったが、SkillEvaluatorはNVIDIAが提唱する3段階パイプラインで静的検証から実動作評価までを一貫して自動化する。arXiv論文（2608.20614）も公開されており、NVIDIA Verified Skillsパイプラインの中核ツールとして研究・産業両面で注目を集めている。

どんな人に役立つか

AIエージェント向けスキルやプロンプト集を開発する研究者・エンジニアに最適なツールである。Claude CodeやCodexなど複数のエージェントへスキルを導入する前の品質ゲートとして活用でき、CI/CDに組み込んで継続的な品質管理も実現できる。

技術的なポイント

  • SkillSpectorと連携した特化型セキュリティスキャンでスキルの静的安全性を解析する
  • オープンソースのエージェント評価フレームワークHarborをDockerサンドボックスで使用しライブ評価を実行する
  • Tier2では埋め込みモデルとチャットモデルを用いてスキル内および複数スキル間の重複を検出する
  • NVIDIA Build APIと統合してルーブリックスコアリングとフィードバック生成によるLLMベース評価を行う
  • Python 3.12・3.13・3.14をサポートし、tier2・tier3・llm・allなどのエクストラで依存を選択できる

試し方

  1. pipまたはuvでSkillEvaluatorをインストールする
  2. uvを使ってPython 3.13環境でbundledサンプルスキルの品質チェックを実行する
  3. レポートはreports/first-qualityディレクトリにCLI出力とJSONで保存される
pip install skillevaluator
uv tool install skillevaluator
uv run --python 3.13 skillevaluator quality-check src/skillevaluator/tier3/reference_skills/text-analyzer -r cli -r json -o reports/first-quality

DuarteSantos8/openGym

Trendshift 18位JavaScriptGitHub ↗

広告・サブスクなしで自分でホストできる筋トレ・ジムトラッカー

何ができるか

  • 5600種以上のエクササイズライブラリと週次ルーティンや周期プランでトレーニングを計画できる
  • セッション中に前回の重量を自動入力し、レスト タイマーやPR検出、プレート計算をサポートする
  • 1RMの推定値・筋肉ボリュームマップ・体重グラフ・進捗写真でトレーニング成果を可視化できる
  • FitNotes・Strong・Hevy・Apple Healthからデータをインポートし、JSON/CSVでエクスポートできる
  • iPhone・iPad・Apple Watch・Androidアプリとして動作し、自サーバーとオフライン単体使用の両方に対応する
  • AIコーチやMCPサーバー、Webhook連携などのオプション機能を必要に応じて有効化できる

なぜ注目されているか

サブスクリプション・広告・テレメトリが一切なく、データを完全に自分でコントロールできる点が支持されている。Dockerで簡単にセルフホストでき、複数デバイス間での同期やパスキー認証にも対応しているため、プライバシー重視のユーザーから注目を集めている。

どんな人に役立つか

ジムでのトレーニングを詳細に記録・管理したいが既存アプリのサブスク料金やデータ収集に抵抗があるユーザーに最適。自宅サーバーやVPSでセルフホストしたいエンジニアや、スマートフォン単体で手軽に使いたいフィットネス愛好者にも向いている。

技術的なポイント

  • データはすべて`./data`フォルダに保存されるためバックアップが容易で、Docker Composeで手軽にデプロイできる
  • パスキー認証（WebAuthn）を採用しており、パスワードレスかつ安全なクロスデバイスサインインを実現している
  • MCPサーバー機能を内蔵しており、AIアシスタントからトレーニングデータへアクセスできる拡張性を持つ
  • AGPL-3.0ライセンスで公開されており、コードの完全な透明性とコミュニティによる貢献が可能になっている

試し方

  1. リポジトリをクローンし、`.env.example`を`.env`にコピーして必要な設定を行う
  2. `docker compose pull`でイメージを取得する
  3. `docker compose up -d`でコンテナを起動する
  4. ブラウザで`http://localhost:8080`を開いてプロフィールを作成する
git clone https://github.com/DuarteSantos8/openGym.git
cp .env.example .env
docker compose pull
docker compose up -d

何ができるか

  • PrometheusやLoki、SQLクエリをページ内で直接実行し、ライブメトリクスやログをドキュメントと並べて表示できる
  • 保護ページへの変更はPRのようなブロックレベルdiff付きのドラフトレビューと承認フローを経由する
  • 複数人がリアルタイムで同じページを編集・コメントでき、ワークスペース横断検索もできる
  • Claude CodeやCodexなどのMCPクライアントが接続でき、AIによる編集も同じレビューフローを通す
  • Anthropic・OpenAI・Google・OpenRouter・Ollamaに対応した組み込みAIアシスタントを内蔵する
  • 単一のDockerコンテナとしてポート8080で起動する、シンプルなセルフホスト構成をとる

なぜ注目されているか

システムの説明とライブデータを同一ページに並置するという独自のアプローチが注目を集めている。AIエージェントとのMCP統合やドラフトレビュー機能が、エンジニアリングチームのドキュメント管理課題を解決する。Apache-2.0ライセンスでオープンに開発されており、コミュニティからの貢献も活発だ。

どんな人に役立つか

自社インフラのメトリクスやログをドキュメントと一緒に管理したいインフラ・SREチームに最適だ。AIエージェントとのコード連携ドキュメントを整備したい開発チームや、セルフホストのWikiソリューションを求めるエンジニアリング組織にも向いている。

技術的なポイント

  • PrometheusやLoki・SQLのクエリ結果をページに埋め込むライブデータ統合アーキテクチャを採用している

V4bel/NoisyTCP

はてなブックマーク 3位3 usersGitHub ↗

Linux TCPスタックの事前認証リモート破損脆弱性PoC（CVE-2026-99288）

何ができるか

  • request_sockの再利用によるABAレース条件を悪用し、NULLリスナー参照とカーネルパニックを引き起こす
  • 子ソケットのABAレースを引き起こし、リモートuse-after-freeを実現する
  • IPv4フラグメントと通常TCPパケットの受信ハッシュの差異を利用してRXキュー間でパケット処理を分散させる
  • 特別な設定不要のNginx・Apache・SSHなど標準的なTCPリスナーを攻撃対象にできる
  • QEMU/KVM環境では約5秒〜2分、ベアメタルサーバーでは最大14時間でトリガー可能なことを実証している

なぜ注目されているか

2015年から2026年まで約11年間存在したLinuxカーネルの重大な脆弱性であり、事前認証でリモートからDoSや潜在的なメモリ破損を引き起こせる点が注目されている。複数のRXキューまたはRPSが有効な一般的なLinuxサーバー（Nginx、Apache、SSHなど）が対象となるため、影響範囲が広く実用的な脅威として評価されている。

どんな人に役立つか

Linuxカーネルのセキュリティ研究者や脆弱性解析者がCVE-2026-99288の攻撃手法を理解・検証するのに役立つ。システム管理者がパッチ適用や一時的な緩和策（SYN Cookie無効化・RXキュー削減）を判断する際の参考にもなる。

技術的なポイント

  • ehashルックアップとrequest_sockの解放・再割り当てのレース条件（ABAパターン）を悪用する
  • IPv4フラグメントと通常TCPパケットで受信ハッシュが異なる特性を利用してRXキュー間にパケットを分散させる
  • SYN Cookieが有効な環境では`net.ipv4.tcp_syncookies=0`を設定することで攻撃を緩和できる
  • カーネル4.1（2015年）から修正コミット4e2b3ef19e0eまでの広い範囲のバージョンに影響する

試し方

  1. 上流の修正コミット（4e2b3ef19e0e）をカーネルに適用してパッチを当てる
  2. 一時的な緩和策としてSYN Cookieを無効化する（コンテナ環境ではネットワーク名前空間ごとに設定が必要）
  3. RXキューを1つに減らしRPSおよびRFSを無効化することで攻撃面を縮小する
sudo sysctl -w net.ipv4.tcp_syncookies=0
