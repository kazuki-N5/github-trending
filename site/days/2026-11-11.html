expo/exact

Trendshift 5位RustGitHub ↗

ContractとTypeScript/Rustで書いたアプリをWeb・macOS・iOS・Linuxでネイティブに動かすクロスプラットフォームランタイム

何ができるか

  • Contractという小さな宣言型言語でUIを記述し、TypeScriptまたはRustでデータロジックを書くことができる
  • WebではリアルなDOMを駆動し、macOS/iOS/LinuxではAppKit・UIKit・GPUペインターなど各プラットフォームのネイティブUIで描画する（WebViewもJavaScriptブリッジも使わない）
  • AIエージェントが10種類の標準操作（tree・screenshot・tap・type等）でアプリをビルド・実行・確認・テストまで完結できる
  • app.test.contractファイルをWeb・macOS・iOS・Linuxすべてで共通して実行できるクロスプラットフォームテストが書ける
  • contract buildコマンドはJSON形式で安定したIDと範囲付き診断を出力するため、AIエージェントがエラーを機械的に処理しやすい

なぜ注目されているか

推測 AIエージェントによるコード生成が普及する中、エージェントがビルド・実行・テストまで無人で完結できるフレームワークへの関心が高まっている。WebViewを使わずに真のネイティブUIをひとつのコードベースで実現する設計がReact Nativeとは異なる新しいアプローチとして注目されている。推測 pre-1.0でも活発に開発されており、AIエージェント時代のアプリ開発モデルを実験するプロジェクトとして話題を呼んでいる。

どんな人に役立つか

クロスプラットフォームアプリをひとつのコードベースで開発したいエンジニア。AIエージェントを使った自動化開発（ビルドからテストまで）に興味がある開発者。React Nativeの代替としてネイティブUIの品質を保ちながらマルチプラットフォーム対応したい人。

技術的なポイント

  • Contractコンパイラがインターフェース記述をコンパクトなプラン（中間表現）に変換し、Webでは約20KBのESモジュールランタイムがそのプランを解釈してリアルDOMを駆動する
  • macOS・iOS・LinuxではRust製のランナーがプランを実行し、RustレイアウトカーネルがCSSルールに基づいて各ボックスを計算する
  • AIエージェント向けに10種類（tree・screenshot・tap・type・state・layout・logs・clock・prefer・perf）の操作APIを全プラットフォームで共通提供しており、テストスクリプトはこれらの操作の記録として機能する
  • clockコマンドでアニメーションを任意の時刻に進められるため、タイミング依存のフレーキーなテストが発生しない設計になっている

試し方

  1. Mac上でXcode・Rust・Bun・Chromeをインストールする
  2. リポジトリをクローンする
  3. bun scripts/exact.mjs setupを一度実行してセットアップを完了する
  4. exact newで新しいアプリを作成する
  5. scripts/agent.mjsでWeb・macOS・iOSシミュレーターにまたがってテストを実行する

FluentRead/FluentRead

Trendshift 9位TypeScriptGitHub ↗

Webページに原文と翻訳を並べて表示するオープンソースのブラウザ拡張機能

何ができるか

  • Webページ全体をバイリンガル表示し、ホバーや選択範囲での翻訳・原文復元・自動翻訳ルール設定ができる
  • AIリーディングカードで意味・文の分析・用例説明・練習問題を段落コンテキスト付きで表示し、追加の質問もできる
  • PDF・ePub・DOCXなどのドキュメントを二言語で読み、翻訳を編集してファイルとしてエクスポートできる
  • YouTubeやXの動画に二言語字幕を表示し、X動画はローカルAI文字起こしも利用できる
  • Webページの画像内テキストを認識して翻訳をオーバーレイ表示・コピーできる
  • 単語・フレーズ・文をオリジナルコンテキスト付きで学習センターに保存してあとから復習できる

なぜ注目されているか

推測 海外の技術情報や論文を読む際の言語の壁を低コストで解決するツールとして支持されており、単なるページ翻訳を超えたAI読解補助機能が他ツールとの差別化になっている。DeepL・各種AIプロバイダー・ローカルOllamaモデルなど多様なバックエンドを選べる柔軟性も評価されている。

どんな人に役立つか

外国語のWebページや技術文書を日常的に読むエンジニア・研究者。語学学習者で原文と訳文を並べて読みながら単語を記録したい人。YouTubeなど外国語動画をバイリンガル字幕付きで視聴したい人。

技術的なポイント

  • TypeScript製のブラウザ拡張機能で、Chrome・Edge・Firefox・ユーザースクリプト（Greasyfork）に対応しておりストアからインストールできる
  • 翻訳バックエンドとして無料サービス・DeepL・各種AIプロバイダー・ローカルのOllamaモデルを選択可能で、用語集や翻訳スタイルも設定できる
  • 設定と学習記録はデフォルトでローカルに保存され、クラウドバックアップはGoogle DriveまたはWebDAVを使って暗号化して同期できる
  • GPL-3.0ライセンスで公開されており、コード・ドキュメント・インターフェース翻訳などのコントリビューションを受け付けている

試し方

  2. 拡張機能アイコンを開いてターゲット言語を選択する（ソース言語は自動検出が可能）
  3. 「ページを翻訳」を選択するとバイリンガル表示になる

ZhuLinsen/daily_stock_analysis

Trendshift 11位PythonGitHub ↗

LLMが毎日株式を自動分析して決策ダッシュボードをチャットツールに通知するPythonシステム

何ができるか

  • A股・港股・米株・日本株・韓国株・台湾株・ETFを対象にLLMが毎日自動で分析レポートを生成する
  • 核心結論・評価スコア・トレンド・売買ポイント・リスク警報・催化因素を含む「決策ダッシュボード」を出力できる
  • 企業WeChat・飛書・Telegram・Discord・Slack・メールなど複数の通知チャネルにレポートを自動送信できる
  • GitHub Actions・Docker・ローカル定時タスク・FastAPIサービスなど複数のデプロイ方式でゼロコスト運用できる
  • AIエージェントによる「策略問股」機能で均線・波浪・トレンド・ホットトピック等15種類の内蔵戦略で多段追問できる
  • WebワークスペースのGUIから手動分析・履歴レポート閲覧・バックテスト・ポジション管理ができる

なぜ注目されているか

推測 個人投資家がLLMを使って株式分析を自動化したいというニーズが高まっており、GitHub Actionsを使ったゼロコスト・サーバー不要の運用方式が導入ハードルを大幅に下げている点が支持されている。多市場対応と複数通知チャネルへの対応が実用性の高さを示しており、A株を含むアジア市場のカバレッジも差別化になっている。

どんな人に役立つか

株式投資をしているが分析に時間をかけられない個人投資家。LLMを活用したfintechシステム（金融技術システム）を作りたいPythonエンジニア。GitHub Actionsを使って無料でデータ分析パイプラインを試したい人。

技術的なポイント

  • AkShare・Tushare・Pytdx・Baostock・YFinance・Longbridgeなど複数の株価データソースをフォールバック付きで統合し、無料ソースのみでもゼロコスト動作する
  • OpenAI互換・Gemini・Claude・DeepSeek・通義千問・Ollamaなど多数のLLMをAPIキー一つで切り替え可能な設計になっている
  • SerpAPI・Tavily・Brave・博查など複数のWeb検索APIを統合して最新ニュース・公告を分析に組み込む
  • GitHub ActionsのスケジュールトリガーでCIとして定時実行することにより、外部サーバーを持たなくても自動化できる

試し方

  1. GitHubでリポジトリをForkする
  2. Settings > Secrets and variables > Actionsで、STOCK_LIST（例: 600519,AAPL）とLLMのAPIキーを設定する
  3. 通知チャネル（Telegram等）のWebhook URLをSecretとして設定する
  4. ActionsタブでワークフローをEnableする
  5. 手動でワークフローをトリガーしてテスト実行する

RunanywhereAI/trnrt

Trendshift 12位PythonGitHub ↗

AWS Trainium2専用のオープンLLM推論エンジン（NKIメガカーネル・100万トークンコンテキスト・OpenAI互換API）

何ができるか

  • AWS Trainium2（trn2.48xlarge）上でOpenAI互換APIとしてLLMを高速サービングできる
  • NKI（Neuron Kernel Interface）メガカーネルにより、デコードを1レイヤー半あたり1カーネルに融合し高効率化する
  • スパースアテンションと線形アテンションを組み合わせて固定サイズのステートで100万トークンのコンテキスト長を実現する
  • FP8 KVページのラディックスツリーとホストメモリ階層によるプレフィックスキャッシュで、キャッシュ済みプロンプトの先頭トークン応答を高速化する
  • グラフコンパイルはCPUホストでオフライン実行し、サービングボックスはコンパイル済みグラフをロードするだけで起動できる

なぜ注目されているか

推測 AWS Trainiumは安価なAI専用ハードウェアだが公式以外の推論ツールが少なく、オープンな実装として希少価値が高い。GLM-5.3-Flash（320B MoEモデル）をスポット価格で100万トークンあたり$0.040という低コストで実行できる点が注目されている。推測 NKIカーネルによる独自最適化の知見を公開したことで、Trainium向けLLM推論研究のベースラインとして関心を集めていると考えられる。

どんな人に役立つか

AWS Trainiumを使ってLLMを低コストで提供したいMLエンジニア・インフラエンジニア。OpenAI APIを代替する自前の推論サーバーを構築したい企業。大規模MoEモデル（複数の小モデルを組み合わせた大規模モデル）の推論最適化に興味がある研究者。

技術的なポイント

  • NKI（Neuron Kernel Interface）でTensorFlow・PyTorchを経由せずKDAアテンション・DSAレイヤー・MoE FFNを融合カーネルとして直接プログラムし、デコードステップを高速化する
  • テンソル並列度32のNeuronCoreにまたがる2エンジン構成とセッションアフィンルーター（同一会話を同じエンジンに転送する仕組み）でプレフィックスキャッシュの効果を最大化する
  • グラフコンパイルはNeuronCoreを持たないx86_64ホストで完結でき、サービングボックスはコンパイル済みグラフをロードするだけで追加コンパイルなしに起動する
  • OpenAI Pythonクライアントで直接使えるOpenAI互換APIとして動作し、ストリーミング・ツールコール・reasoning outputも対応している

試し方

  1. 任意のx86_64ホストでDockerイメージをビルドする
  2. コンパイルキャッシュを生成する（NeuronCore不要だが数時間かかる）
  3. 生成したキャッシュとモデルをtrn2.48xlargeにコピーする
  4. trn2.48xlarge上でDockerコンテナとしてサービングを起動する
  5. OpenAI Pythonクライアントでlocalhost:8000に接続して動作確認する
git clone https://github.com/RunanywhereAI/trnrt.git && cd trnrt
docker build -f docker/Dockerfile --build-arg TRNRT_VERSION=$(python3 -c 'import trnrt; print(trnrt.__version__)') --build-arg TRNRT_REVISION=$(git rev-parse HEAD) -t trnrt .
trnrt compile shapes zai-org/GLM-5.3-Flash --revision $REV --out $OUT
trnrt compile decisions --model zai-org/GLM-5.3-Flash --revision $REV --out $OUT
trnrt compile capture --out $OUT -- --model $OUT/shapes
trnrt compile compile --out $OUT --work-root $OUT/work
trnrt compile strip --out $OUT
docker run --rm --privileged --network host --ipc=host -v /data/trnrt/cache:/cache -v /data/trnrt/nki:/var/tmp/nki-intermediate-cache -v /models/GLM-5.3-Flash:/model -e NEURON_LIBTORCH_CACHE_ROOT=/cache trnrt serve --model /model --port 8000

minorun365/unslop-ai-app

はてなブックマーク 4位3 usersJavaScriptGitHub ↗

AIエージェントに読ませるとAI臭くない画面を作れるスキル集

何ができるか

  • AIが作りがちな「余計な部品・絵文字・宣伝風の見出し」を避けるためのデザイン規則（app-ui-design）が含まれている。
  • エージェントのチャット画面固有の作法（考え中表示・ログイン画面・人前で操作する画面）をまとめたスキル（agent-app-ui）がある。
  • スマホ表示をiOS Simulatorで確かめる手順とiOS Safari固有の罠をまとめたスキル（mobile-web-check）がある。
  • 依存ライブラリ不要の検査スクリプト（check-ui.mjs）でソースコードからAIらしい書き方を自動検出できる。
  • 修正前後の比較サンプル（examples/）が付属しており、スキルの効果を確認できる。

なぜ注目されているか

AIエージェントが生成するWebアプリのUI品質は実際の開発現場で課題になっており、その解決策をスキル形式にまとめた珍しいアプローチが注目されている。日本語の組版や画面文言まで踏み込んでいる点が日本語圏の開発者に特に役立つ。

どんな人に役立つか

Claude CodeなどのAIエージェントを使ってWebアプリを開発するエンジニア・デザイナーに役立つ。日本語向けのUI品質を高めたいAIアプリ開発者に特に向いている。

技術的なポイント

  • Claude Codeのスキル機能（~/.claude/skills/に配置するMarkdownファイル）を使ってAIエージェントへ指示を渡す仕組みになっている。
  • check-ui.mjsはNode.js標準機能だけで動作し、外部パッケージへの依存がない。
  • スキル本文はAIエージェントだけでなく人間が読んでも理解できる日本語で書かれている。
  • Damir SokolovskyのUnslop（CC BY 4.0）を参考に日本語画面向けに書き直した内容を含んでいる。

試し方

  1. ClaudeデスクトップアプリのCodeタブまたはClaude Codeを開く。
  2. 「https://github.com/minorun365/unslop-ai-app のスキルを入れて」と依頼する。
  3. 新しいセッションを開始して、「このダッシュボード、なんかAIっぽいので直して」などと普通の言葉で頼む。
node ~/.claude/skill-repos/unslop-ai-app/tools/check-ui.mjs src/

geekfujiwara/powerpoint-agent-skills

はてなブックマーク 5位3 usersGitHub ↗

PowerPointのCopilotエージェントモード向けスキル集（日英対応）

何ができるか

  • スライドの主張に合わせて図解の型（比較・フロー・階層・収束など）を最適化するスキル（optimize-slide-diagram）がある。
  • 明暗2種のテーマ・表紙・区切りページのデザインを統一するスキル（presentation-theme）がある。
  • カードに収まるフラットイラストを挿入するスキル（slide-illustrations）がある。
  • 重複生成された図形を検出・整理するスキル（remove-duplicate-shapes）がある。
  • フェードインと下からの順次表示アニメーションを付けるスキル（fade-in-rise-animation）がある。
  • ロングテール図・階層図・工程図など目的別の図解作成スキルが複数含まれている。

なぜ注目されているか

Microsoft 365のCopilot（エージェントモード）という普及しているツールをより便利に使うためのスキルをまとめた実用的なコレクションとして注目されている。日英両対応で公開されており、日本語でも英語でもすぐに使える点が評価されている。

どんな人に役立つか

Microsoft 365のPowerPoint Copilotを日常的に使う社会人・ビジネスパーソンに最適。スライド作成の繰り返し作業を自動化したいプレゼン作成者に役立つ。

技術的なポイント

  • スキルファイルはYAMLヘッダー付きのMarkdownファイル（SKILL.md）として作成し、OneDriveの特定フォルダーに配置することでCopilotが認識する。
  • Agent Skills標準仕様（agentskills.io）に準拠したフォーマットを採用している。
  • GitHubのActionsによってスキルファイルの形式とZIP構造を自動検証している。
  • スキルは独立したフォルダー単位で管理されており、必要なものだけを選んで導入できる。

試し方

  1. GitHubのReleasesページから全スキル入りのZIPをダウンロードしてPCで展開する。
  2. PowerPointのCopilot → + → Choose plugins → Manage plugins → Open skills folderを開く。
  3. 展開したスキルフォルダーをOneDriveのスキルフォルダー直下にコピーする。
  4. OneDriveの同期を待ち、PowerPointのスキル管理画面でRefreshを押して使いたいスキルを有効にする。
  5. Copilotの入力欄の「+」→「プラグインの選択」から使いたいスキルを選ぶか、@スキル名で指定する。

crmne/zapfast

はてなブックマーク 6位3 usersRustGitHub ↗

RustとeguiでできたネイティブWhatsAppデスクトップクライアント

何ができるか

  • テキスト・画像・ファイル・スタンプ・GIF・投票・音声メッセージの送受信ができる。
  • 動画・音声メッセージ・GIFをアプリ内でそのまま再生できる。
  • チャット履歴を暗号化してローカルに保存し、テキストやZIPでエクスポートできる。
  • 複数のWhatsApp番号を1つのウィンドウで管理できる。
  • アプリロックやロックチャットでプライバシーを保護できる。
  • ライト・ダーク・システムテーマに加え、カスタムカラーテーマを作成・適用できる。

なぜ注目されているか

WhatsApp Webに比べて起動が約1秒と瞬時で、アイドル時のメモリ使用量が約200MB（WhatsApp Webは1.13GB）と大幅に軽い点が注目されている。ブラウザエンジンを使わない完全ネイティブなRustアプリという技術的な珍しさも話題になっている。

どんな人に役立つか

Linux・macOS・WindowsでWhatsAppを軽快に使いたいデスクトップユーザー全般に向いている。リソースの少ない環境や、ブラウザを開きたくない環境でWhatsAppを使いたい人に特に役立つ。

技術的なポイント

  • RustのGUIフレームワーク「egui」とfastframeを使ってブラウザエンジンなしのネイティブUIを実現している。
  • whatsapp-rustライブラリを通じてスマートフォンのコンパニオンデバイスとしてQRコードでリンクする仕組みになっている。
  • ネイティブ通知はLinux・macOS・WindowsでFastframeを使って実装されており、通知クリックで対象メッセージを開くことができる。
  • チャット履歴は暗号化してデバイスにのみ保存し、開発者のサーバーへのデータ送信は一切行わない。

試し方

  1. macOSはHomebrewでインストールするか、公式サイトからMacアプリをダウンロードする。
  2. Arch LinuxはAURからインストールする。
  3. WindowsはGitHubリリースページからインストーラーを選ぶ。
  4. 起動後に表示されるQRコードをスマートフォンのWhatsApp（設定→リンク済みデバイス→デバイスをリンク）でスキャンする。
brew install --cask crmne/tap/zapfast
yay -S zapfast-bin
cargo run --features demo -- --demo
