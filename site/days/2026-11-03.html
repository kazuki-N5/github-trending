どんな人に役立つか

技術的なポイント

  • オプションでGhidraを統合してより高度なディスアセンブル・デコンパイルを行うことができる
  • Claude CodeをはじめACP（Agent Communication Protocol）対応の各種エージェントと連携できる設計になっている

試し方

  1. Rust 1.97以上をインストールする
  2. リポジトリをクローンしてビルドする、またはCLIをcargoでインストールする
  3. ターゲットのWebサイト・アプリ・ゲームを指定して解析を開始する
  4. Study→Build→Check→Refineの4ステップに従い再構築を進める

JiaFeiMiao-K-Cat/DiscImageStudio

Trendshift 7位C#GitHub ↗

画像をCD・DVD・BD-Rのディスク面に焼き付けてデザインを可視化するツール

何ができるか

  • 画像データをCD・DVD・BD-Rの物理的なディスク面に印刷できる形式に変換できる
  • Windowsデスクトップアプリでデザインから書き込みまで一貫して行える
  • キャリブレーション支援ワークフローでディスクの物理パラメータを最適化できる
  • IMAPI2を使用したWindowsネイティブの直接ストリーミング書き込みにも対応している（実験的）
  • ディスクにデータファイルも同時収録できる
  • 簡体字中国語・繁体字中国語・英語・日本語の多言語UIに対応している

なぜ注目されているか

推測 ディスクメディアへのビジュアル印刷という独自のニッチに特化しており、類似ツールが少ないため注目されていると考えられる。CD・DVD・BDという3世代のメディアをすべてカバーし、オフラインで動作してテレメトリなしというプライバシー配慮の設計も評価されている。

どんな人に役立つか

コレクター向けや特別なプレゼント用にオリジナルデザインのディスクを作りたいユーザーに役立つ。音楽や映像を配布する際にパッケージ性を高めたいアーティストやクリエイターにも適している。

技術的なポイント

  • .NET 10 SDKで実装されており、リリースパッケージには.NETランタイムが同梱されている
  • CD出力はWAV/CUEまたはRAWオーディオ形式、DVD出力はISO形式、BD-RはUDF 2.01をサポートする
  • ECMA-394（CD-R）・ECMA-267（DVD-ROM）・ECMA-359（DVD-R）・ISO/IEC 30190:2021（BD-R）などの標準規格を参照している
  • Windows IMAPI2を通じた実験的な直接ストリーミング書き込み機能を実装している

試し方

  1. Windows 10 2004以降またはWindows 11の環境を用意する
  2. GitHubリリースページからインストーラーまたはポータブルパッケージをダウンロードする
  3. アプリを起動してキャリブレーションワークフローを実行する
  4. 画像をデザインしてISO・WAV/CUEなど対応形式でエクスポートするか、直接書き込みを行う

Verlintas/NOIR

Trendshift 8位KotlinGitHub ↗

Androidデバイスの情報漏洩リスクをadb経由で監査し修正案を提示するデスクトップツール

何ができるか

  • 接続したAndroidデバイスのアプリごとにネットワーク・センシティブ権限の一覧を取得できる
  • APKのdexファイルからURLエンドポイントを抽出してテレメトリ・広告・位置情報などに分類しリスクスコアを付与する
  • 権限とデータ種別（位置情報・連絡先・SMS・カメラ等）を紐付けて報告ドメインとのマッピングを行う
  • バイナリAXMLを解析してエクスポートコンポーネント・クリアテキスト通信・バックアップ設定などのマニフェスト問題を検出する
  • 安全な自動適用項目・手動確認項目・触れてはいけない項目に分類したロールバックコマンド付き推奨事項を出力する
  • jadxを使用して単一APKをDeepScanし`Runtime.exec`や`DexClassLoader`などの高リスク呼び出しを検索できる

なぜ注目されているか

推測 ルート不要・アカウント不要・ネットワーク通信なしでAndroidデバイスのプライバシーリスクを可視化できる点が評価されていると考えられる。スマートフォンのデータ収集に対するユーザーの関心が高まる中、自分のデバイスを手軽に監査できるツールとして注目を集めている。

どんな人に役立つか

自分のAndroidデバイスやアプリが何を外部に送信しているか把握したいプライバシー意識の高いユーザーに役立つ。セキュリティ研究者や企業のIT管理者が許可を得たデバイスの監査に使用するケースにも適している。

技術的なポイント

  • Kotlin（Compose Multiplatform）で実装されており、macOS・Windows・Debian/Ubuntuに対応している
  • adbを通じてデバイスと通信し、unzipとstringsをデバイス上で実行してAPKからエンドポイントを抽出する
  • jadxを使用したDeepScan機能でAPKを逆コンパイルして高リスクなAPIコールをソースレベルで検索する
  • JDK 17以上が必要だが、ポータブルリリースはランタイムを同梱しているため不要

試し方

  1. macOS・Windows 10/11・Debian/Ubuntuいずれかの環境にJDK 17以上とAndroid platform-toolsをインストールする
  2. GitHubリリースページからポータブルパッケージをダウンロードする（JDK不要）
  3. AndroidデバイスをUSBデバッグ有効でPCに接続する
  4. `noir`を起動してセットアップウィザードに従いスキャンを実行する
  5. 生成されたreport.json・report.md・plan.txt・rollback.txtを確認して推奨事項を適用する

noir scan
noir auto --apply
noir deepscan

thtbee/nectarlink

Trendshift 12位RustGitHub ↗

AndroidスマホとWindows PCをローカルかつ暗号化で連携させるオープンソースアプリ

何ができるか

  • PC上でスマホの通知・SMS・チャット（WhatsApp、Signalなど）を確認・返信できる
  • クリップボードを暗号化して共有し、パスワードやワンタイムコードは除外される
  • ファイルやフォルダを双方向で転送でき、写真へのアクセスやリンクの引き渡しも可能
  • スマホ画面をPC上でミラーリングし、アプリを独立したウィンドウで操作できる
  • スマホをPCのウェブカメラやスピーカーとして利用できる
  • PCからスマホをタッチパッドやキーボードでリモート操作できる

なぜ注目されているか

推測 MicrosoftのPhone Linkのようなクローズドな競合に対し、アカウント不要・クラウド不使用・エンドツーエンド暗号化というプライバシー重視の設計が差別化ポイントとして注目されている。オープンソースである点も透明性を求めるユーザーからの支持につながっている。

どんな人に役立つか

プライバシーを重視しつつAndroidスマホとWindows PCを密に連携させたいユーザー向け。アカウント登録やクラウドへのデータ送信を避けたい技術系ユーザーに特に適している。

技術的なポイント

  • Rust製の共有コアライブラリにより、WindowsとAndroid間のプラットフォーム共通ロジックを実装している
  • WindowsアプリはQt Quickで、AndroidアプリはJetpack Composeで実装され、各プラットフォームのネイティブUIを提供している
  • 暗号鍵はWindowsのDPAPIとAndroidのKeystoreで保護され、デバイス間はUSBまたはローカル直接接続で通信する
  • オプションのモバイルデータ経由リレー接続ではトラフィックの内容を読めない設計になっている

試し方

  1. GitHubのReleasesページからWindows x64インストーラーをダウンロードしてインストールする
  2. GitHubのReleasesページからAndroid APKをダウンロードしてサイドロードする
  3. 両アプリを起動してペアリング手順に従いデバイスを接続する

e-Govの法令APIから生成した、改正ごとにコミットが積み上がる日本法令のgitリポジトリ

何ができるか

  • 日本の法令をe-Gov法令APIから取得し、各改正が施行された順にgitコミットとして積み上げることで法令の変遷をgit履歴で追跡できる
  • git show <コミット> で特定の改正がどの条文をどう変えたかをdiff形式で確認できる
  • 法令ファイルはMarkdown形式で、YAMLフロントマターに法令IDや施行日などのメタデータを持つ
  • mainブランチには施行済みの改正のみ、upcomingブランチには公布済みで未施行の改正が管理されている
  • git grep や git log -L を使ったコマンドラインでの法令検索・条文の変更履歴追跡が可能になっている

なぜ注目されているか

推測 日本の法令は頻繁に改正されるが、従来のe-Govサイトでは差分を視覚的に確認しにくかった。gitのdiff機能で改正内容を即座に把握できるこのアプローチは開発者や法律を扱う技術者に刺さる独自の切り口として注目されている。推測 リーガルテックへの関心の高まりとgitを活用したデータ管理の斬新さが話題を呼んでいる。

どんな人に役立つか

日本の法令改正の内容や履歴をプログラムで調べたいエンジニア・リサーチャーに役立つ。法律条文の差分確認やリーガルテック開発の素材として活用できる。ただし官報や公式テキストの代替ではなく、重要な判断前には必ずe-Govや官報で原文を確認することが推奨されている。

技術的なポイント

  • gitのコミット日時を施行日に設定し、コミットトレーラーに改正法令ID・施行日・国会提出法案番号などのメタデータを埋め込む設計になっている
  • 法令ファイルはlaws/<法令種別>/<ID先頭3文字>/<e-Gov法令ID>.md という階層構造で管理されている
  • 表はHTMLで記述し、図はe-Govの添付ファイルへのリンクで表現している
  • MarkdownリントはuvxでrumdlをインストールしてCIと手動確認に使用している
  • データはe-Gov法令検索のPDL1.0ライセンスに基づき、法令テキスト自体は著作権法第13条により著作権がないとされている

試し方

  1. リポジトリをクローンしてローカルに取得する
  2. git grep で法令名から対象ファイルのパスを特定する
  3. git log や git show で改正の履歴や差分を確認する
  4. 特定条文の変更履歴はgit log -L でファイル内の行範囲を指定して追跡する
git grep -l '^title: "個人情報の保護に関する法律"' -- laws
git log -L '/^##*  *第十六条/,/^##*  *第十七条/:laws/act/415/415AC0000000057.md'
uvx rumdl@0.2.79 check

はてなブックマーク 3位3 usersGitHub ↗

コード・画像・バイナリを内容に応じたアルゴリズムで差分表示するTUIツール

何ができるか

  • 25言語をtree-sitterで構文解析してコンテンツ対応の差分アルゴリズムで比較できる
  • 画像・アーカイブ・フォント・PDF・メッセージカタログなどバイナリ形式も内容を認識して差分表示できる
  • インタラクティブTUIモードとヘッドレス（--headless/--batch）モードの両方で使用できる
  • JSON出力モード（--mode json）でCI/CDパイプラインへの組み込みも可能
  • GitおよびJujutsuのdifftoolとして設定でき、設定ウィザードコマンドも提供している
  • VS CodeとNeovimのエディタ統合プラグインを提供している

なぜ注目されているか

推測 単一の差分ツールでコード・バイナリ・画像を一括して扱えるオールインワン設計が開発者の興味を引いていると考えられる。tree-sitterによる言語認識で意味のある差分を提供し、中央値4.2ms・p99 177msという高速性能も評価されている。Claude Codeを活用した開発プロセスの透明性ある開示もコミュニティの関心を集めている。

どんな人に役立つか

コードレビューやリポジトリ変更の確認に差分ツールを頻繁に使う開発者に役立つ。GitやJujutsuのdifftoolを高機能なものに置き換えたいエンジニアや、CI/CDで差分情報をJSON形式で活用したい自動化担当者にも適している。

技術的なポイント

  • Rustで実装されており、`cargo install --locked omnidiff`でインストールできる（Cコンパイラとrustc 1.92以上が必要）
  • tree-sitterを使用して25言語を構文解析し、言語固有のコンテンツ対応差分アルゴリズムを適用している
  • ファイル内容のバイトシグネチャで形式を識別するため、拡張子に依存せず画像・PDF等を自動認識できる
  • AGPL-3.0ライセンスで、商用利用向けにはGitHub Sponsorsを通じた商用ライセンスを提供している

試し方

  1. rustc 1.92以上とCコンパイラをインストールする
  2. cargoでomnidiffをインストールするか、GitHubリリースページからプレビルドバイナリをダウンロードする
  3. `omnidiff BEFORE AFTER`で2つのファイルを比較するインタラクティブTUIを起動する
  4. `?`キーでキーバインド一覧を表示して操作を確認する
  5. `omnidiff git configure`でGitのdifftoolとして設定する
cargo install --locked omnidiff
omnidiff BEFORE AFTER
omnidiff --headless BEFORE AFTER
omnidiff git configure
omnidiff jj configure
GIT_EXTERNAL_DIFF=omnidiff git diff
