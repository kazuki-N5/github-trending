Zagitta/gpu-unlock

Trendshift 1位CGitHub ↗

RTX 3000番台のBF16演算レートをプロ用GPU相当に解放するLinuxカーネルモジュール

何ができるか

  • GeForce RTX 3000番台（GA102/103/104/106チップ）のFP/BF16（浮動小数点・脳浮動小数点）演算発行レートをプロ用カード相当に引き上げる。
  • RTX 3090 TiではBF16 GEMMのスループットが87.50 TFLOPSから157.41 TFLOPSへほぼ倍増する。
  • LLMのプリフィル・画像生成（拡散モデル）・FlashAttentionなど行列演算が主体のワークロードを高速化する。
  • サスペンド（スリープ）から復帰した後も自動的にアンロックを再適用する。
  • NVIDIAドライバのバージョンアップに依存せず、カーネルモジュール単体で動作するため再パッチが不要。

なぜ注目されているか

GeForce RTX 3000番台はプロ向けカード（A6000等）と同じシリコンダイ（半導体チップ）を使っているにもかかわらず、ファームウェアの設定でBF16演算レートが半分に絞られている。このモジュールはその制限を起動時に解除し、実ハードウェアの潜在能力を引き出せる。LLM推論・学習や画像生成が普及する中、高価なプロ用GPUを買わずに同等性能を得られるコスト効率の高い手段として注目されている。

どんな人に役立つか

GeForce RTX 3000番台でLLM推論・ファインチューニングや拡散モデル推論を行うLinuxユーザーに役立つ。プロ用GPUへの投資を抑えながら機械学習ワークロードを高速化したい研究者やエンジニアに向いている。Linuxカーネルモジュールのビルドとインストール、ブートローダー設定の編集ができる技術知識が必要。

技術的なポイント

  • Linuxカーネルモジュールとして実装されており、NVIDIAドライバがGPUにbind（接続）する前に先行ロードしてGPUのレジスタ設定を直接書き換える。
  • mkinitcpio・initramfs-tools・dracut向けのパッケージフックが用意されており、initramfs（ブート初期段階の一時RAMファイルシステム）に組み込んで早期ロードを実現する。
  • カーネルコマンドラインパラメータ`gpu_unlock.targets`でPCIアドレスを指定し、アンロック対象GPUを絞り込める。
  • PM_POST_SUSPENDフック（電源管理の復帰イベント）を利用し、サスペンド後に設定を自動再適用する。

試し方

  1. リポジトリをクローンする。
  2. `make install`を実行してカーネルモジュールをビルドしインストールする。
  3. ブートローダーのカーネルコマンドラインに`gpu_unlock.targets=all`を追加して再起動する。
make install

  • Tinker を使用してオープンソースモデルのファインチューニング（特定用途向けの追加学習）が可能

  2. `exp` コマンドを実行し、セットアップウィザードでプロバイダー・モデル・予算などを設定してワンタイムキーを取得する

openJiuwen-ai/jiuwenswarm

Trendshift 6位PythonGitHub ↗

チャットアプリ経由で使えるマルチエージェント協調フレームワーク（スウォーム型）

何ができるか

  • Leaderエージェントが複雑なタスクを分解し、専門エージェントチームを編成して並列処理する
  • SwarmflowでPythonスクリプトによる決定的なマルチステージワークフローを定義し、human-in-the-loop（人間が確認しながら進める）ステップも組み込める
  • スキルの自己進化機能により、エラーやユーザーの不満を検知してスキル定義を自動的に改善する
  • Skill Hubでスキルの検索・インストール・リミックス・公開が可能なコミュニティエコシステムを提供する
  • Telegram・Discord・Slack・WhatsAppなど国内外の主要チャットアプリから直接AIエージェントを操作できる
  • ツール実行前の承認要求やファイルアクセスのホワイトリスト管理など複数のセキュリティ機能を備える

なぜ注目されているか

日常的に使うチャットアプリ（Slack・DingTalk・Telegramなど）からそのままAIエージェントを呼び出せる点が実用的なハードルを大きく下げている。単体のチャットボットではなくLeader-Workerによる「スウォーム（群）」として複数エージェントが自律的に連携する設計は、複雑な業務自動化の需要に応えている。推測 マルチエージェント協調がLLM活用の次のステップとして注目される中、既存コミュニケーションツールへの統合容易性が採用を後押ししていると考えられる。

どんな人に役立つか

Slack・DingTalk・Feishuなどのチャットツールを業務で使っている開発者や企業担当者に向いている。複雑な繰り返し作業を複数エージェントで自動化したいエンジニアや、LLM（大規模言語モデル）を既存のワークフローに組み込みたいチームに役立つ。

技術的なポイント

  • Python 3.11以上が必要で、uv（高速なPythonパッケージマネージャー）による仮想環境管理を採用している
  • OpenAI互換API・Huawei Cloud MaaSおよびローカルモデルに対応し、多様なLLMバックエンドを利用できる
  • Leader-Workerのマルチエージェントアーキテクチャにより、タスクを複数プロセス・マシンへ分散実行できる
  • MCP（Model Context Protocol）・A2A・E2AプロトコルによるAIエージェント間の相互連携をサポートしている
  • Auto Harness機能により、モデルの重みを変更せず評価ベースでハーネス（エージェントの動作設定）自体を最適化する

試し方

  1. pip install workswarm でパッケージをインストールする（中国圏向けのミラーも利用可能）
  2. jiuwenswarm-init を実行して初期設定を行う
  3. jiuwenswarm-start を実行してサーバーを起動する
  4. ブラウザで http://localhost:5173 を開いてWebUIにアクセスする
  5. WebUIの「More → Configuration」でデフォルトモデルを設定する
pip install workswarm

xevrion/hatchzip

Trendshift 7位RustGitHub ↗

アーカイブを縮小しながら展開し、出力ファイル分のディスク容量だけで巨大ZIPや7zを解凍できるツール

何ができるか

  • 展開しながらアーカイブを縮小するため、出力ファイル分の空き容量だけで解凍できる（アーカイブと展開後ファイルの合計は不要）
  • 展開前に空き容量が足りるかチェックし、途中でディスクが満杯になる事態を防ぐ
  • 途中で停止・クラッシュしても、同じコマンドを再実行するだけで再開できる
  • ZIP、7z、tar、tar.gz、RARボリュームセット、分割アーカイブに対応
  • ファイルをディスクに書き込んでからアーカイブを削る順序を守り、CRC-32（チェックサム：データ破損検出用の値）で各ファイルを検証する

なぜ注目されているか

180 GB のダウンロードを200 GBに展開する場合、従来ツール（WinRAR・7-Zip・unzip）では両方合わせて380 GB の空き領域が必要だったが、HatchZip なら約200 GB で済む。推測 ストレージが限られるゲーマーやダウンロードサイズが大きい開発者の間で話題になっていると考えられる。

どんな人に役立つか

大容量ゲームや配布ファイルをダウンロードするユーザーで、ストレージの空き容量が少ない人に特に役立つ。サーバー管理者やCI環境など、ディスク使用量を最小化したい場面でも活用できる。

技術的なポイント

  • Rust 製のCLIツールで、Cargo でビルド・インストールできる
  • 展開と同時にアーカイブの末尾を切り詰めることで、ディスク使用量をリアルタイムに削減する
  • 進行状況を2つのサイドファイル（.hatchzip と .hatchzip-tail）に保存し、再開可能にしている
  • RAR サポートは UnRAR ソースを利用する別ライセンス機能で、`--features rar` フラグでオプトイン（任意有効化）できる
  • MIT または Apache-2.0 のデュアルライセンスを採用し、企業・個人どちらも利用しやすい

試し方

  1. インストールスクリプトまたは Cargo でインストールする
  2. `hatchzip check archive.zip` で空き容量が足りるか確認する
  3. `hatchzip extract archive.zip` で展開を開始する（途中停止後も同じコマンドで再開できる）
curl -fsSL https://raw.githubusercontent.com/xevrion/hatchzip/main/install.sh | sh
cargo install hatchzip
brew install xevrion/tap/hatchzip
winget install Xevrion.HatchZip
hatchzip check game.zip
hatchzip extract game.zip
hatchzip extract game.zip -o D:\Games\Foo
hatchzip x game.7z.001
hatchzip list game.7z
hatchzip test game.7z
hatchzip restore game.zip

ludovic111/horizon

Trendshift 10位RustGitHub ↗

Minecraft Java版をRustでゼロから再実装した完全互換クライアント

何ができるか

  • バニラ（公式版）と同じワールド生成・Mob・レッドストーン・コマンドをシングルプレイヤーで再現する
  • 281件のディファレンシャルハーネス（バニラとの自動差分比較テスト）で公式との挙動一致を継続検証している
  • WebAssembly（ブラウザ等でも動く軽量なバイナリ形式）ベースの独自Modシステムを持つ
  • Modrinth・CurseForgeのModpackからデータパック・アセットModをインポートできる
  • horizon-ctlというCLIツールおよびMCPサーバー経由でAIエージェントやスクリプトからゲームを制御できる
  • 専用ランチャーでサーバーを管理でき、Javaなしでhorizon-serverをVPS上で動かせる

なぜ注目されているか

RustによるMinecraftの完全再実装という技術的挑戦と、281件の差分テストによる検証可能な互換性保証が注目を集めている。推測 ネイティブコードによるパフォーマンス向上や、公式ランチャー・Javaへの依存を排除した独立性の高さも評価されている可能性がある。

どんな人に役立つか

Minecraftを軽量・高速な環境でプレイしたいユーザーや、ゲームエンジン実装をRustで学びたいエンジニアに向いている。AIエージェントでMinecraftを自動操作したい研究者・開発者にも、MCP（Model Context Protocol）サーバー機能を通じて有用なプラットフォームとなる。

技術的なポイント

  • Rust 1.90以上でゲーム全機能をゼロから実装し、ガベージコレクションなしの高速・省メモリな実行を実現している
  • Vulkan（GPU向けの低レベルグラフィクスAPI）を採用したレンダリングエンジンを持つ
  • WebAssemblyをMod実行サンドボックスとして使用し、Javaコードなしの安全な拡張を可能にしている
  • research-lock.jsonにハッシュ値を管理し、ビルド時にユーザー自身のMinecraftインストールからリソースを生成することで著作物を同梱しない設計になっている
  • horizon-ctl mcp コマンドでMCPサーバー（AIエージェントとの連携規格）として機能し、外部からゲーム状態を操作できる

試し方

  1. Minecraft 26.3を正規購入し、少なくとも1回起動しておく
  2. Java 25 JDKをインストールする（初回セットアップの一度限り必要）
  3. Vulkan対応GPUを用意する（LinuxまたはWindowsを使う場合）
  4. Horizonランチャーを公式サイトからダウンロードしてインストールする（Linux x86-64・macOS Apple Silicon・Windows x64に対応）
  5. ランチャーからHorizonを起動する

マクドナルドMCPで1年分の食事の炭素排出量を計算・削減シミュレーションするツール

何ができるか

  • 食品・包装・配達の3層モデルで炭素排出量（CO2換算）を推定する
  • マクドナルド公式MCP（AIエージェント連携プロトコル）を通じて注文履歴・栄養データをリアルタイム取得できる
  • セット商品を個別アイテムに自動分解して正確な計算を行う
  • 牛肉→鶏肉への変更やデリバリー→持ち帰りへの切り替えなど、削減効果をシミュレーションできる
  • 炭素グレード（A〜E）・月別トレンド・木換算距離換算を含む単一ファイルのHTMLレポートを生成する
  • MCPトークンなしで試せるオフラインデモモードも用意されている

なぜ注目されているか

推測 MCP（Model Context Protocol）というAIエージェント連携の新技術を実際のサービスAPIに適用した珍しい実装例として注目されている。個人の食生活を具体的な炭素数値で可視化するアイデアの新鮮さもあり、コンテスト応募作品として創造的なMCP活用事例として評価されやすい。外部ライブラリゼロで動く実用ツールという点も関心を集めやすい。

どんな人に役立つか

マクドナルドをよく利用し自分の食事の環境負荷を把握・改善したい人に役立つ。MCPの具体的な実装例やPythonによる炭素排出量計算の仕組みを学びたいCS学生にも参考になる教材的な価値がある。

Claude Code・Cursor・Codexなどのコーディングエージェントを使って動画編集ワークフローを自動化したい開発者に役立つ。APIキー不要でオフライン動作するため、プライバシーを重視するユーザーやCI/CDパイプラインに動画処理を組み込みたいエンジニアにも適している。

技術的なポイント

  • Python標準ライブラリのみを使用しており、外部Pythonパッケージへの依存がない
  • argparse（Pythonの引数解析ライブラリ）の定義からMCPツールのスキーマを自動生成している
  • `contract --json`コマンドで各ツールの入出力・要件を機械読み取り可能なJSON形式で提供する
  • MCP（Model Context Protocol：AIエージェントがツールを呼び出すための標準プロトコル）サーバーとして動作する
  • Linux・macOS・Windows上でCIテストを実施し、FFmpeg 5.1〜9.x の複数バージョンに対応している

試し方

  1. FFmpegをシステムにインストールする（macOSはHomebrewを使用、WindowsやLinuxは公式バイナリや各パッケージマネージャー経由）
  2. `npx ffmpeg-skill`を実行して、使用するエージェント向けにスキルをインストールする
  3. `npx ffmpeg-skill doctor`を実行して、FFmpegとツールの依存関係が正しく揃っているか確認する
npx ffmpeg-skill
npx ffmpeg-skill doctor
