ccch1mneyyy/dsh-Go

Trendshift 1位GitHub ↗

Android向け非公式DSHクライアント。ローカル実行またはリモートPC操作に対応。

何ができるか

  • ルートやTermuxなしにAndroid端末内にUbuntu環境・Node.js・DSHをインストールし、スマホ単体でAIエージェントをローカル実行できる。
  • SSHまたはDSH Remoteを使ってPCやサーバー上のDSHをスマホからリモート操作できる。
  • モデル切り替え・画像添付・音声入力・ツール承認・Webモードなど多彩なチャット機能を備える。
  • プラグインSDKを通じてネイティブのツールカード・フォーム・パネルを自作・追加できる。
  • スクリーン読み取り・タップ・入力などスマホ操作をAIに実行させることができ、ユーザーがいつでも停止できる。
  • 会話の共有・エクスポート・再生や、テーマ・アイコン・デスクトップペット（DeepyとJingniang）によるカスタマイズが可能。

なぜ注目されているか

DeepSeek HarnessをPCなしにスマホで直接動かせる珍しいアプローチが注目されている。推測 Androidデバイスの処理性能向上により、スマホでのローカルAIエージェント実行が現実的になってきた背景があると考えられる。推測 リモートPC操作機能によりスマホとPCを連携した新しいAI活用スタイルを提案している点も関心を集めている可能性がある。

どんな人に役立つか

DeepSeek HarnessをPCなしに外出先から使いたいユーザーや、Androidスマホだけでものを作りたいエンジニアに向いている。また、SSHでサーバー上のDSHをスマホからリモート操作したい開発者にも役立つ。

技術的なポイント

  • FlutterフレームワークをベースにAndroidアプリを構築しており、arm64（主要端末向け）とx86_64（エミュレーター向け）のAPKを提供している。
  • ルートやTermuxなしにアプリ内でUbuntu環境を構築し、その中でNode.jsとDSHを動かす独自のローカルランタイム技術を採用している。
  • SSHおよびDSH Remoteプロトコルでリモートサーバー上のDSHに接続し、スマホをフロントエンドとして操作できる。
  • プラグインSDKとサンプルコードをMITライセンスで公開しており、ネイティブUIコンポーネント（カード・フォーム・パネル）を備えた拡張機能を開発できる。

試し方

  1. Android 8.0（API 26）以降の端末を用意する
  2. GitHub Releasesまたは公式ダウンロードページからarm64向けAPKをダウンロードしてインストールする
  3. アプリ起動後にローカルランタイムまたはリモートホストを選択し、使用するモデルを設定する

thedotmack/claude-mem

Trendshift 3位TypeScriptGitHub ↗

AIエージェントのセッション間でコンテキストを永続化する記憶圧縮システム。

何ができるか

  • セッション中のツール使用を観察してAIが意味的なサマリーを生成し、将来のセッションに自動的に引き継げる。
  • SessionStart・PostToolUse・Stopなど複数のライフサイクルフック（セッションの各段階で自動実行される処理）でエージェントの行動をキャプチャする。
  • MCPツール（search・timeline・get_observations）によりセッション横断の記憶をハイブリッド検索（テキスト＋ベクトル）できる。
  • `<private>` タグで機密情報をコンテキスト注入から除外し、プライバシーを守れる。
  • Claude Code以外にもOpenCode・DeepSeek Harness・Gemini CLIなど多くのAIエージェントと連携できる。
  • cmem.aiへのクラウド同期機能により複数端末間で記憶を共有できる。

なぜ注目されているか

AIコーディングエージェントはセッションをまたぐとコンテキストが失われ、毎回同じ説明を繰り返す必要があるという課題がある。推測 Claude Code・OpenCode・Codexなど多くのエージェントが普及するにつれ、セッション間記憶の欠如が実用上の大きなボトルネックになっていると考えられる。推測 LLMのコンテキストウィンドウ節約（約10倍のトークン削減を主張）という経済的メリットも注目を集める要因と思われる。

どんな人に役立つか

Claude CodeやOpenCodeなどのAIコーディングエージェントを日常的に使う開発者で、セッションをまたいでプロジェクトの文脈を引き継ぎたい人に向いている。複数のAIエージェントを横断的に使い分けるエンジニアにも有用である。

技術的なポイント

  • TypeScriptで実装されたライフサイクルフック（Claude Codeプラグインシステム対応）により、ツール呼び出しの前後やセッション開始・終了時に記憶の読み書きを行う。
  • SQLiteデータベース（軽量なファイルベースDB）でセッション・観察・サマリーをローカル保存し、Chromaベクトルデータベース（意味的類似検索用）でセマンティック検索を実現している。
  • Bunで管理されるローカルワーカーサービスがHTTP APIとWebビューアを提供し、蓄積された記憶を管理・閲覧できる。
  • 3層ワークフロー（search→timeline→get_observations）で段階的にコンテキストを絞り込み、不要なトークン消費を抑えて約10倍のトークン節約を実現すると主張している。

試し方

  1. Node.js 20以上がインストールされていることを確認する
  2. ターミナルで `npx claude-mem install` を実行するか、Claude Code内で `/plugin marketplace add thedotmack/claude-mem` を実行する
  3. Claude Code内で `/plugin install claude-mem` を実行してプラグインを有効化する
  4. サインインして30日間の無料トライアルを開始するか、`--provider` フラグでオフライン利用を選択する

microsoft/TokenEconomizer

Trendshift 5位PythonGitHub ↗

コーディングエージェントの実行コストをブラックボックスのまま自動削減するプラグイン

何ができるか

  • マイクロスキル機能により、リポジトリ固有の知識（テストコマンドなど）を複数セッションから自動学習し、次回セッション冒頭で共有することで無駄な試行を削減する。
  • ツール剪定（Tool Pruning）により、複数のプロンプトやセッションにわたって使われないツールをエージェントの設定から自動除去し、コンテキスト消費を減らす。
  • ループガード（Loop Guard）により、エージェントが同じ処理を繰り返している場合に判定モデルが検知し、リダイレクト通知を送って無限ループによる無駄なコストを防ぐ。
  • Claude Code・Codex・GitHub Copilot CLI・Piなど複数のコーディングエージェントに対応しており、エージェント本体のコードを変更せずにプラグインとして導入できる。
  • SWE-Benchの評価では5つのエージェント・モデルの組み合わせで平均18.4〜30.9%のコスト削減を達成し、うち4つでPass@1スコアも向上した。

なぜ注目されているか

推測 LLMを使ったコーディングエージェントの利用コストが急増する中、エージェント本体を改変せずコストを削減できる手法として注目を集めていると考えられる。UC Berkeley・Microsoft Research・Microsoft Securityの共同研究としてarXivに論文（2610.22732）が公開されており、学術的な裏付けがあることも関心を集める要因と推測される。推測 実際のSWE-Benchベンチマークで精度を落とさずコスト削減を示した実証結果が、エンジニアや研究者にとって実用性の高いツールとして評価されているとみられる。

どんな人に役立つか

Claude CodeやGitHub Copilot CLIなどのAIコーディングエージェントを業務や研究で使いながらAPIコストを抑えたい開発者向け。エージェントの動作原理を変えずにコスト最適化を行いたいチームや組織にも適している。

技術的なポイント

  • Python 3.10以上で動作し、学習データは~/.tokeneconomizerディレクトリにローカル保存されるため外部サービスへのデータ送信が不要。
  • ツール剪定はエージェントが持つ設定ファイルを直接操作することで実現しており、restore用の1コマンドで元の状態に戻せる。
  • ループガード判定には別途モデル呼び出しを行うため、プラグイン自体のモデル呼び出しコストも計測結果に含まれた上でのコスト削減効果が報告されている。
  • マイクロスキルはデフォルト無効（追加モデル呼び出しが発生するため）で、TE_DISABLE=1などの環境変数やconfig setコマンドで各機能の有効・無効を切り替えられる。

試し方

  1. 各エージェントのプラグインマーケットプレイスからインストールする（opencode の場合はリポジトリをクローンしてファイルをリンク）。
  2. Python 3.10以上がインストールされていることを確認する。
  3. 通常通りエージェントを使用する。プラグインが自動的に動作し、~/.tokeneconomizerにデータを蓄積する。
  4. 設定を変更する場合はconfig setコマンドまたはTE_DISABLE=1などの環境変数を使用する。

lexifina/global-law

Trendshift 10位HTMLGitHub ↗

世界各国の法律をGitの履歴として管理し、任意の日付の法令テキストを参照できるリポジトリ

何ができるか

  • 国連加盟193カ国を含む世界の法域（jurisdiction）の法律をGitサブモジュールとして管理し、1つのリポジトリで全世界の法令履歴を参照できる。
  • 各コミットが「特定の日付における全法令の状態」を表すよう設計されており、git logやgit diffを使って法律の変遷を追跡できる。
  • MCP（Model Context Protocol）サーバーをローカルで起動することで、AIアシスタントが自然言語で法令検索・比較・引用解決などを行えるようになる。
  • コマンドラインツール（tools/law.py）を使って、指定日付の法令表示・差分比較・特定の条文が誰に（いつ）編集されたかの追跡などが可能。
  • manifest.jsonで各法令コーパスのカバレッジや履歴種別を管理しており、法全体から一部の法律のみをカバーするものまで複数種類の収録形式に対応している。

なぜ注目されているか

推測 法律文書のバージョン管理という独自のコンセプトが技術コミュニティの関心を引いており、従来は専門家しかアクセスしにくかった各国の法令をGitという馴染みのあるツールで扱えるという斬新さが注目を集めていると考えられる。推測 MCPサーバーを通じてAIアシスタントと連携できる設計は、法律AIアプリケーション開発者にとって有用なデータソースとなるため、関心が高まっているとみられる。推測 CC0ライセンスで公開されていることも、研究・開発用途での利用を促進し普及に貢献していると推測される。

どんな人に役立つか

法令のバージョン管理や時系列での変遷調査を行いたい法律研究者・法学者向け。MCPを使ってAIと法令データを連携させたいLegalTech開発者にも適している。比較法学や国際法の研究者にとっても複数国の法律を一元管理できる点で有用。

技術的なポイント

  • Gitサブモジュール（git submodule）を使って各国の法令リポジトリ（lexifina/<country>-law）を1つの親リポジトリに統合しており、git clone --recurse-submodulesで全データを取得できる。
  • MCPサーバー（tools/mcp_server.py）はPython 3.10以上とgitが必要で、stdioを通じてローカル動作し、ネットワーク通信を行わない読み取り専用の設計。
  • tools/build.pyを使って決定論的（同じ入力から常に同じ結果が得られる）にリポジトリをビルドでき、REPRODUCE.mdにハッシュレベルの再現手順が記載されている。
  • Gitは1970年1月1日以前の日付を保存できないため、In-forceトレーラーフィールドを正式な施行日として扱う設計になっており、遡及立法はコミットメッセージに記録される。
  • jurisdiction.jsonで世界の法域ツリーを定義し、manifest.jsonで各法令コーパスのソースリポジトリ・カバレッジ・履歴種別（in-force/replayed/current-only）を管理している。

試し方

  1. リポジトリをサブモジュールごとクローンする（全データ取得の場合）。
  2. サブモジュールを初期化・更新する（--recurse-submodulesなしでクローンした場合）。
  3. tools/law.pyを使って特定日付・パスの法令を表示・比較する。
  4. MCPサーバーを使う場合はclaudeコマンドでサーバーを登録する。
git clone --recurse-submodules https://github.com/lexifina/global-law && cd global-law
git clone https://github.com/lexifina/global-law && cd global-law
git submodule update --init
python tools/law.py world 2022-05-01
python tools/law.py show 2022-05-01 <path>
python tools/law.py blame 2022-07-01 <path>
python tools/law.py words 2022-07-01 <path>
python tools/law.py diff 2022-05-01 2022-07-01 <path>
python tools/law.py laws 1990-01-01 1990-12-31 germany
claude mcp add global-law -- python tools/mcp_server.py
python -m unittest discover -s tests -v

HeyPuter/everything

Trendshift 12位JavaScriptGitHub ↗

商用ソフトウェアをゼロからオープンソースで再構築するモノレポプロジェクト

何ができるか

  • オフィス系アプリ（スプレッドシート、ドキュメント、プレゼンテーション、PDF等）を無料の代替として提供する。
  • コラボレーションツール（会議、チームチャット、メール、カレンダー等）をまとめて収録している。
  • フォトスタジオやビデオスタジオなどのクリエイティブツールも含まれている。
  • CADや回路設計などのエンジニアリング向けアプリも提供する。
  • CRMやヘルプデスクなど13種類のビジネス向けアプリも揃っている。
  • チェスや数独などのゲームアプリも収録されている。

なぜ注目されているか

推測 Adobe、Microsoft、Slack などの高額な商用ソフトウェアへの代替需要が高まっており、オープンソースで一括提供するという野心的なコンセプトが注目を集めていると思われる。推測 MIT ライセンスで公開されているため、個人・企業問わず自由に利用・改変できる点も人気の理由の一つと考えられる。51種類ものアプリを単一リポジトリで管理するモノレポ構成という大規模プロジェクトとしての話題性もある。

どんな人に役立つか

高価な商用ソフトウェアの代替を探している個人や中小企業に適している。オープンソースのアプリ開発に貢献したい開発者や、自社サーバーにセルフホストして使いたい組織にも向いている。

elementary-swift/elementary-ui

はてなブックマーク 2位3 usersGitHub ↗

SwiftUIスタイルの宣言的APIでブラウザ上で動くWebアプリを構築できるSwiftフロントエンドフレームワーク

何ができるか

  • SwiftUIに似た宣言的なビューAPIでUIコンポーネントを記述できる。
  • @State・@Environment・@Reactiveを使ったリアクティブな状態管理が組み込まれている。
  • Embedded Swift（組み込み向け最適化コンパイルモード）によってWebAssemblyバンドルサイズを小さく保てる。
  • CSSアニメーションとFLIPトランジション（要素位置変化を自動アニメーションする技術）を標準サポートしている。
  • Viteベースの開発サーバーとホットリロードによって快適な開発体験を提供する。
  • ElementaryWebComponentsライブラリで型安全なWebコンポーネントを定義できる。

なぜ注目されているか

SwiftはiOSやmacOS開発では広く使われているが、フロントエンドWeb開発には一般的に使われてこなかった。推測 WebAssembly技術の成熟とEmbedded Swiftの登場により、Swiftエコシステム全体でフルスタック開発ができる可能性が現実的になってきたことが注目を集めている要因と思われる。

どんな人に役立つか

SwiftやSwiftUIに慣れたiOS/macOS開発者でWebフロントエンドも同じ言語で書きたい人や、WebAssemblyベースのSwift Webアプリ開発に興味を持つエンジニアに向いている。

技術的なポイント

  • WebAssembly（Wasm）：Swiftコードをブラウザで実行可能なバイナリ形式にコンパイルする技術で、Swift 6.4以降とswift.orgのWasm向けSwift SDKが必要。
  • Embedded Swift：メモリ使用量を抑えるためのコンパイル最適化モードで、標準ランタイムの多くを省略し小さなWasmバンドルを生成する。
  • FLIP（First Last Invert Play）トランジション：DOM要素の位置変化を自動検出してアニメーション補間する手法で、宣言的UIと自然に組み合わせられる。
  • Elementary（サーバーサイドHTMLレンダリングライブラリ）を基盤とし、そのコンポーネントモデルをブラウザのリアクティブUIに拡張している。

試し方

  1. Swift 6.4以降をインストールし、swift.orgからWebAssembly向けSwift SDKを追加する。
  2. Package.swiftにElementaryUIを依存関係として追加する。
  3. Viteベースの開発サーバーを起動してブラウザで確認する。
  4. Examplesディレクトリ内のSwiftleデモアプリを参考にする。
