headroomlabs-ai/headroom

GitHub Trending 7位★ +310PythonGitHub ↗

AIエージェントがLLMに渡す情報を手元で圧縮し、トークンを節約するツール

何ができるか

  • ツールの出力、ログ、RAG（検索で集めた資料をLLMに渡す手法）の検索結果、ファイル、会話履歴を、LLMに送る前に圧縮します。
  • Python・TypeScriptのライブラリとして compress(messages) で使うほか、コードを変えずに挟めるプロキシ（中継サーバー）としても動きます。
  • headroom wrap claude のように1コマンドで、Claude Code、Codex、Aider、Cline などのコーディングエージェントを Headroom 経由で動かせます。
  • MCP（AIツールと外部機能をつなぐ共通規格）サーバーとして、圧縮・元データ取得・統計の機能を提供します。
  • 圧縮前の元データを手元に保存しておき、モデルが必要なときに全文を取り出せるようにします（CCR）。
  • モデルの前置きや無駄な繰り返しを抑えるよう促すなど、モデルが書き返す出力トークンも減らせます。

なぜ注目されているか

README によると、SRE障害調査のシナリオで55,957トークンを24,340トークンへ57%削減しつつ、GSM8K などの精度評価では差がほとんど出なかったと示されています。圧縮処理は1ミリ秒前後と速く、手元のマシンで動くためプロンプトやファイルの中身を外部に送らずに済みます。推測 AIコーディングエージェントの利用が広がりAPI料金やコンテキスト長の制約が問題になっているため、既存のエージェントにそのまま組み込める点が注目されていると考えられます。

どんな人に役立つか

Claude Code や Codex などのAIエージェントを日常的に使い、API料金やコンテキストの上限に悩んでいる人に役立ちます。大量のログやJSONをLLMに読ませるアプリを作っている開発者にも向いています。

技術的なポイント

  • ContentRouter が内容の種類を判定し、JSONは SmartCrusher、ソースコードは AST（構文木）を使う CodeCompressor、文章は Hugging Face で公開された Kompress-v2-base モデルへ振り分けて圧縮します。
  • CacheAligner は、プロバイダ側のKVキャッシュ（同じ前置き部分の計算結果を再利用する仕組み）を壊しやすい変動部分を検出します。プロンプトは書き換えません。
  • Anthropic の /v1/messages や OpenAI 互換の /v1/chat/completions などのAPI形式に対応するプロキシとして、間に入って通信を処理します。
  • headroom learn は失敗したセッションを分析し、CLAUDE.md や AGENTS.md などの指示ファイルに修正内容を書き込みます。

試し方

  1. pip または uv で headroom-ai をインストールします（CLIはPyPI版にのみ含まれます）。
  2. headroom wrap claude でエージェントを包むか、headroom proxy --port 8787 でプロキシを起動します。
  3. headroom doctor で動作を確認し、headroom dashboard で節約できたトークン量を確認します。
uv tool install --python 3.13 "headroom-ai[all]"
pip install "headroom-ai[all]"
npm install headroom-ai
headroom deploy
headroom wrap claude
headroom proxy --port 8787
headroom doctor
headroom perf
headroom dashboard

withmarbleapp/os-taxonomy

GitHub Trending 8位★ +284JavaScriptGitHub ↗

子どもが学ぶ内容を前提関係のグラフにまとめたオープンな学習項目データセット

何ができるか

  • 小学校段階で学ぶ内容を、ひとつずつ教えられる1,591個の「マイクロトピック」に細かく分け、説明・習得の目安（evidence）・対象年齢を付けて収録しています。
  • 「トピックXを学ぶにはトピックYが先に必要」という前提関係3,225本を、hard/soft の強さと一行の理由付きで有向非巡回グラフ（DAG：向きがあり循環しないグラフ）として提供します。
  • 各トピックを NGSS、Common Core、英国ナショナルカリキュラムなど、各国のカリキュラム標準に対応づけています。
  • 理科と算数・数学の1,051トピックについて、教え方・具体的な学習活動・評価の方法・参考文献をまとめた「教授法リサーチ」データを含みます。
  • 科目・分野・年齢帯ごとに、保護者向けの一段落の要約（176件のクラスタ）を用意しています。
  • Science・Mathematics・English・History など8科目をカバーしています。

なぜ注目されているか

推測 カリキュラムのデータは標準の平坦な一覧か、製品の中に閉じ込められたものが多いのに対し、前提関係でつながった「学習のグラフ」を誰でも使える形で公開した点が注目されていると考えられます。商用利用もできるライセンス（ODbL・CC BY-SA）で出されているため、教育アプリや AI チューターの開発者にも使いやすいデータになっています。

どんな人に役立つか

教育アプリや学習支援 AI を作る開発者、カリキュラムやグラフ構造データを研究したい人に役立ちます。ある概念を学ぶ前に何を身につけておくべきかをたどる、学習順序の設計に使えます。

技術的なポイント

  • 実行環境や依存ライブラリはなく、UTF-8 の JSON ファイルだけで構成された純粋なデータセットです。
  • トピックがグラフのノード、前提関係（topicId が prerequisiteId に依存）がエッジになっていて、エッジを逆向きにすれば「次に解放される内容」が得られます。
  • schema/ に JSON Schema（JSON の構造を定義する仕様）があり、manifest.json には件数と各ファイルの SHA-256 チェックサムが記録されています。
  • teaching-research.json は topics.json の正確なバイト列に topicFileSha256 で結び付けられていて、トピックファイルが変わったら作り直す仕組みです。
  • Node.js 用の検証スクリプト（validate.mjs）とテスト（node --test）で、構造・カバー範囲・チェックサムを確認できます。

試し方

  1. リポジトリを取得し、data/ フォルダにある topics.json と dependencies.json を JavaScript などから読み込みます。
  2. トピックの id から名前を引ける Map を作り、dependencies を topicId で絞り込むと、そのトピックの前提トピックの一覧が得られます。
  3. 教え方の情報が必要なら teaching-research.json を topicId で結合します（現在は理科と算数・数学のみ対応）。
  4. 検証スクリプトとテストを実行して、データの構造やチェックサムを確認します。

node --test scripts/teaching-research.test.mjs

anthropics/claude-code

GitHub Trending 11位★ +167TypeScriptGitHub ↗

ターミナルで動き、自然言語の指示でコーディングを手伝うAIエージェント

何ができるか

  • ターミナル上でコードベース全体を理解したうえで、自然言語の指示に従ってコーディング作業を手伝います。
  • よくある定型作業を実行したり、複雑なコードを説明したりできます。
  • git の操作（コミットやブランチ管理などの一連の作業）を自然言語で任せられます。
  • ターミナルだけでなく IDE（統合開発環境）からも使え、GitHub 上で @claude とメンションして呼び出すこともできます。
  • プラグインでカスタムコマンドやエージェントを追加し、機能を拡張できます。
  • /bug コマンドで、Claude Code の中から直接不具合を報告できます。

なぜ注目されているか

Anthropic が公式に提供するエージェント型（AI が自分で手順を考えてツールを操作する方式）のコーディングツールで、ターミナル・IDE・GitHub と普段の開発環境にそのまま組み込める点が特徴です。推測 AI に開発作業を任せる「エージェント型コーディング」への関心が高まっており、その代表的なツールとして注目されていると考えられます。

どんな人に役立つか

ターミナルで開発することが多く、コードの読解や定型作業、git 操作を AI に手伝ってほしい開発者に向いています。初めて触る大きなコードベースの理解を助けてもらう用途にも使えます。

技術的なポイント

  • 動作には Node.js 18 以上が必要とされています。
  • コマンドラインツール（CLI）として提供され、プロジェクトのディレクトリで claude コマンドを実行して使います。
  • このリポジトリには、カスタムコマンドやエージェントを追加する Claude Code 用プラグインがいくつか含まれています。
  • インストールは公式のインストールスクリプト、Homebrew、WinGet などで行い、npm 経由のインストールは非推奨になっています。

試し方

  1. お使いの OS に合った方法で Claude Code をインストールします。
  2. 開発中のプロジェクトのディレクトリに移動します。
  3. claude コマンドを実行して、自然言語で指示を出します。

shiyu-coder/Kronos

GitHub Trending 12位★ +363PythonGitHub ↗

株価などのローソク足データを予測する、金融市場向けのオープンソース基盤モデル

何ができるか

  • 過去のローソク足（K線: 始値・高値・安値・終値・出来高などをまとめた価格データ）から、指定した未来の期間の値を予測できます。
  • KronosPredictor クラスが前処理・正規化・予測・逆正規化をまとめて行うので、数行のコードで予測を出せます。
  • 温度 T や top_p、sample_count といったパラメータで、サンプリングによる確率的な予測を制御できます。
  • predict_batch メソッドで複数の銘柄や期間を GPU 上でまとめて並列に予測できます。
  • mini（410万パラメータ）から base（約1億パラメータ）までの学習済みモデルが Hugging Face Hub で公開されています。
  • Qlib を使った中国A株データでのファインチューニング（追加学習）とバックテスト（過去データでの戦略検証）の一連のスクリプトが付属しています。

なぜ注目されているか

README によると、金融のローソク足データ向けとしては初のオープンソース基盤モデル（大量データで事前学習し、さまざまなタスクに流用できるモデル）で、世界45以上の取引所のデータで学習されています。論文が arXiv で公開され AAAI 2026 に採択されたこと、BTC/USDT の24時間先予測を見られるライブデモがあることも紹介されています。推測 汎用の時系列モデルではなく、ノイズの多い金融データに特化した点が関心を集めていると考えられます。

どんな人に役立つか

株価や暗号資産の価格予測を試したい人、クオンツ（数理的な手法で行う投資）の研究や時系列予測モデルに興味がある人に向いています。自分のデータでファインチューニングして独自のタスクに合わせたい場合にも使えます。

技術的なポイント

  • 連続値で多次元のローソク足データ（OHLCV）を、専用のトークナイザーで階層的な離散トークン（記号の列）に量子化します。
  • そのトークン列で、デコーダのみの自己回帰型 Transformer（前のトークンから次のトークンを順に予測するモデル）を事前学習する2段階構成です。
  • モデルとトークナイザーは Hugging Face Hub から from_pretrained で読み込みます。入力できる長さ（コンテキスト長）は small と base で512、mini で2048です。
  • ファインチューニングは torchrun による複数 GPU での学習に対応し、トークナイザーと予測モデルを順に追加学習します。

試し方

  1. Python 3.10 以上を用意し、requirements.txt の依存パッケージをインストールします。
  2. KronosTokenizer と Kronos を Hugging Face Hub から読み込み、KronosPredictor を作成します。
  3. open・high・low・close 列を含む pandas の DataFrame と、過去・未来のタイムスタンプを用意します。
  4. predictor.predict を呼び出して予測結果の DataFrame を得ます。データ読み込みからグラフ描画までの完全な例は examples/prediction_example.py にあります。
  5. 自分のデータで追加学習する場合は pyqlib を入れ、finetune/config.py のパスを設定してから、データ前処理・トークナイザー学習・予測モデル学習・バックテストの順にスクリプトを実行します。
pip install -r requirements.txt
pip install pyqlib
python finetune/qlib_data_preprocess.py
torchrun --standalone --nproc_per_node=NUM_GPUS finetune/train_tokenizer.py
torchrun --standalone --nproc_per_node=NUM_GPUS finetune/train_predictor.py
python finetune/qlib_test.py --device cuda:0

Gathin23/cleanyourtv

Trendshift 1位JavaGitHub ↗

Android TV の広告と不要アプリを消し、Apple TV 風のホーム画面にするツール集

何ができるか

  • Wi-Fi 経由の ADB（Android の開発者向けデバッグ接続）で、メーカーのテレメトリ（利用状況の送信）や広告サービス、プリインストールアプリを無効化できます。
  • アプリはアンインストールせず pm disable-user で無効化するだけなので、restore スクリプト1行で元に戻せます。
  • 約300KBの軽量ネイティブランチャー（ホーム画面アプリ）をインストールし、お気に入り4アプリのドック、フォーカス中アプリ名の表示、グリッド表示などを備えた Apple TV 風のホームにできます。
  • Claude Code などシェルを使えるコーディングアシスタントに PROMPT.md を渡すと、TV の検出・バックアップ・不要アプリの洗い出し・ランチャーのビルドとインストールまでを対話的に進めてくれます。
  • 25ブランド66機種分の検証済み無効化リストが examples/ に用意され、テーマ切り替え、時計スクリーンセーバー、14言語対応も備えています。

なぜ注目されているか

README に引用された作者の投稿によると、両親の TV で Netflix を開く前にスポンサー広告が出るのを、Claude Code に型番を伝えるだけで解消したという話が発端で、その投稿への返信から多くの機種別リストが集まりました。推測 root 化不要で元に戻せる手軽さと、AI コーディングアシスタントに作業を任せる「バイブコーディング」の実例として話題になったと考えられます。

どんな人に役立つか

Android TV や Google TV のホーム画面の広告やおすすめ表示にうんざりしている人に向いています。ADB や Android アプリのビルドの流れを実機で学びたい学生にとっても、手順とスクリプトがそろった教材になります。

技術的なポイント

  • ランチャーは素の Java と AndroidX RecyclerView だけで作られ、ブラー・動画・ネットワーク通信・常駐サービスを使わず、メモリ 1GB の TV でも動くよう設計されています。
  • tools/tv.py は Python だけで書かれた ADB クライアントで、macOS などで標準の adb コマンドが使えない環境でもシェル実行やファイル転送ができます。
  • 大きな APK は b64push.py で base64 に分割して送り、チェックサムで検証します。
  • インストールスクリプトは現在のホームアプリを TV に問い合わせ、新しいランチャーがホームにならなければ元に戻すロールバック処理を持ちます。
  • テーマは TV に送る config.json で色・壁紙・ドック・列数を変えられ、ランチャーを再ビルドする必要がありません。

試し方

  2. TV と同じ Wi-Fi につながったコンピューターで、Claude Code などのアシスタントに PROMPT.md を貼り付け、TV の型番を書き込みます。
  3. TV に出る「USB デバッグを許可しますか？」を承認し、使うアプリやドックに置く4アプリなどのチェックリストに答えます。
  4. 手動で行う場合は、Python 3 の仮想環境を作って TV_HOST に TV の IP アドレスを設定し、tools/ のスクリプトで確認・無効化・復元、launcher/build-and-install.sh でランチャーを導入します。

kksimp/Mac.apk

Trendshift 3位JavaGitHub ↗

Apple Silicon搭載MacでAndroidアプリをエミュレータなしでそのまま動かすアプリ

何ができるか

  • Androidアプリ（APK）を普通のmacOSのプロセスとして起動し、MacのGPUで描画し、CPU上でネイティブ速度で実行します。
  • 起動したアプリはDockに表示され、信号機ボタン（ウィンドウ左上の3つのボタン）の横に戻るボタンが付いた独自のウィンドウを持ちます。
  • ウィンドウのリサイズや回転ができ、Macのライトモード・ダークモードの切り替えにも追従します。
  • Mac.apkのコントロールパネルからアプリの管理やアンインストールができ、アプリストアの使い方や詳しい設定（Flags、開発者メニュー）はWikiで説明されています。
  • .apkに加えて.apkm・.xapk・.apks・.apkxの形式に対応し、ダブルクリックやドラッグ＆ドロップでインストールできます。
  • 手作業で66本のアプリを検証した互換性リストを公開しており、52本が完全に遊べる状態と報告されています。

なぜ注目されているか

エミュレータや仮想マシン（別のOSを丸ごと模擬する仕組み）を使わず、Linuxカーネルも動かさずに、AndroidのアプリケーションをmacOS上で直接動かすという珍しいアプローチを取っているためです。推測 Apple Silicon MacでAndroidアプリを軽快に使いたい人が多く、Apple の署名・公証済みですぐ試せる点も関心を集めていると考えられます。

どんな人に役立つか

Apple Silicon搭載のMac（macOS 26.4以降）でAndroid専用のアプリやゲームを使いたい人に向いています。OSの互換レイヤーやランタイムの実装に興味がある人にとっても、ソースコードを読む価値があります。

技術的なポイント

  • Androidフレームワーク（アプリが使うAndroidの標準API群）をmacOS上に再実装し、Androidそのものを起動せずにアプリを動かします。
  • arm64向けのローダーと、Androidの標準Cライブラリ「Bionic」の差を埋めるシム（互換用の薄い層）で、アプリ内のネイティブコードを実行します。
  • 古い32ビットARM向けコードは、ARM32リコンパイラ（別の命令セット向けの機械語に変換する仕組み）で動かします。
  • 描画にはANGLE（OpenGL ESを他のグラフィックAPIへ変換するライブラリ）やMoltenVK（VulkanをAppleのMetal上で動かすライブラリ）などを同梱して使っています。
  • Javaコード実行用にOpenJDKからビルドしたJREを同梱しており、ライセンスはGNU AGPL v3.0で、商用ライセンスも用意されています。

試し方

  1. ReleasesページからディスクイメージをダウンロードしてMac.apkをアプリケーションフォルダにドラッグします。
  2. Mac.apkを開き、左上の「Runtime:」の横にある「Install」をクリックしてランタイムを入れます。
  3. 設定（歯車）の「File types」で「Make Default」をクリックし、macOSの確認を承認します。
  4. 任意の.apk（または.apkm、.xapk、.apks、.apkx）をダブルクリックするか、Mac.apkのウィンドウにドラッグしてインストールします。
  5. 初回起動は準備のため最大1分ほどかかりますが、2回目以降は速く起動します。信頼できる入手元のAPKだけを使い、アンインストールはゴミ箱ではなくコントロールパネルから行います。

Trendshift 6位TypeScriptGitHub ↗

自分のPCで動き、普段使うチャットアプリから話しかけられるオープンソースAIアシスタント

何ができるか

  • Discord、iMessage、Slack、Teams、Telegram、WhatsApp など20以上のチャットサービス（チャネル）から同じアシスタントに話しかけられる。
  • macOS、iOS、Android、Windows、Linux 向けのネイティブアプリがあり、音声、Canvas、カメラ、画面操作、端末上での操作などを追加できる。
  • Claude や Codex、ローカルモデルなどの AI モデルやエージェント実行基盤をプラグインとして差し替えられる。
  • ツール、スキル、プラグインでアシスタントの能力を拡張でき、プラグインは ClawHub で共有できる。
  • ブラウザで開く管理画面（Control UI）、CLI、TUI（ターミナル上の画面）から操作できる。
  • 同じ Gateway を、ノートPC上の個人用アシスタントとしてもチーム共有の環境としても、設定の違いだけで動かせる。

なぜ注目されているか

状態・記憶・認証情報を自分のハードウェアに置き、有料プランやホスト型サービスを持たない、非営利財団（OpenClaw Foundation）が運営するオープンソースのアシスタントである点が特徴として打ち出されている。推測 普段使いのチャットアプリからそのまま AI に作業を頼める手軽さと、データを手元に残せる安心感の両立が、多くの開発者の関心を集めていると考えられる。

どんな人に役立つか

Slack や Telegram などのチャットから AI に作業を任せたい人や、データを外部サービスに預けずに自分の PC で AI アシスタントを動かしたい人に向いている。チームで共有するアシスタントを自前で運用したい場合にも使える。

技術的なポイント

  • TypeScript で書かれた Node.js アプリで、リポジトリは pnpm ワークスペース（複数パッケージを1つにまとめて管理する仕組み）として構成されている。
  • Gateway がローカルの制御の中心（コントロールプレーン）となり、セッション、ツール、イベント、チャネル接続を管理する。
  • 「信頼できる Gateway と信頼しない実行環境を分け、ポリシーをコードで強制する」という設計で、受信メッセージは信頼できない入力として扱い、未知の送信者はペアリング承認が必要になる。
  • ツールは標準ではホスト上で実行されるが、サンドボックス（隔離された実行環境）を設定して動かすこともできる。
  • 新しい機能はプラグイン SDK を使ったプラグインとして作るのが基本で、モデルやエージェント実行基盤も差し替え可能なプラグインになっている。

試し方

  1. インストーラ（macOS / Linux / WSL2 はシェルスクリプト、Windows は PowerShell）を実行するか、Node.js を管理済みなら npm でパッケージを入れる。
  2. インストーラ経由ならオンボーディング（初期設定ウィザード）が自動で始まるので完了させ、npm などで直接入れた場合は openclaw onboard --install-daemon を実行する。
  3. オンボーディングではモデルへのアクセス確認、作業用ワークスペースの作成、Gateway の設定が行われる。
  4. openclaw gateway status で状態を確認し、openclaw dashboard で Control UI を開いてメッセージを送り、アシスタントが動くことを確かめる。

openclaw onboard --install-daemon
openclaw gateway status
openclaw dashboard
