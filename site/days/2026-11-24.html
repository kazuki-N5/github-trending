AFK-surf/xnulinux

Trendshift 2位Objective-C++GitHub ↗

LinuxカーネルモジュールとしてXNUを動かし、macOSとLinuxを同一CPU上で並列実行するプロジェクト

何ができるか

  • XNUカーネル（macOSのオープンソースカーネル）をLinuxのカーネルモジュール（xnu.ko）としてロードできる。
  • ハイパーバイザーなしで、macOSプロセスとLinuxプロセスが同一のCPU上で並走する。
  • FKIモジュール（fki.ko）を通じて、XNUがLinuxのメモリ・タイマー・ファイル・ネットワーク・GPUを利用できる。
  • Apple SiliconのMac上でarm64 Linux VMを動かす構成と、NVIDIA DGX Sparkのベアメタル構成の両方でmacOSデスクトップが起動することを確認済み。
  • VulkanブリッジによりホストGPUをmacOS側から利用できる（DGX Sparkは現時点でCPUレンダリング）。
  • systemdサービスとして登録し、起動時にmacOS環境を自動実行する設定が可能。

なぜ注目されているか

推測 macOSの動作をLinuxカーネルモジュールとして実現するという従来にない大胆なアプローチが、OS研究者やハッカーの注目を集めている。ハイパーバイザーを使わず、LinuxとmacOSを同一CPU上で共存させる点は技術的に非常に挑戦的であり、Apple Siliconの普及とあわせて関心が高まっていると考えられる。

どんな人に役立つか

OSの内部実装やカーネル開発に興味があるエンジニアや研究者向け。arm64 Linux環境でmacOSアプリケーションを動かしたい開発者や、カーネルモジュール・仮想化技術を学びたい人にも参考になる。

技術的なポイント

  • XNUカーネルをAppleの公開ソースからビルドし、Linuxのカーネルモジュール（.ko）形式でロードする仕組みを採用している。
  • FKIインターフェース（GPL-2.0）がXNU側コード（APSL-2.0）とLinuxカーネルを橋渡しし、メモリ・タイマー・ファイルシステム・ネットワーク・GPUを共有する。
  • PAC（Pointer Authentication Code）サポートと4Kページを持つarm64 Linuxホストが必要で、メモリは16GB以上が要件。
  • VulkanブリッジでLinuxホストのGPUをmacOS側から透過的に使用できる構成になっている。
  • Appleのバイナリは一切含まず、ビルド時にアップストリームのソースを取得する設計のため、ライセンス的にクリーンな構成を維持している。

試し方

  1. arm64 LinuxホストにXNUカーネルとkextをビルドする。
  2. Macで自分のmacOS 27インストール済みディスクをホスト用ディスクに変換する。
  3. 付属のスクリプトでmacOS環境を起動する。
  4. 任意でsystemdサービスに登録してブート時に自動起動させる。

os6/nospeaker

Trendshift 6位SwiftGitHub ↗

MacBookのForce Touchトラックパッドの触覚モーターを音声スピーカー代わりに駆動するツール

何ができるか

  • Macをミュートした状態でも、トラックパッドの触覚モーター（ハプティクス）から音声を出力できる。
  • macOSの音声合成（テキスト読み上げ）と組み合わせて、任意のテキストをトラックパッドで「話す」ことができる。
  • 利用する音声を他のmacOS音声に切り替えるオプションがある。
  • 周波数スイープ（音の高さを連続変化させるテスト信号）の出力にも対応している。
  • one-lineのcurlスクリプト、署名済みzipリリース、またはXcodeソースビルドの3通りでインストールできる。

なぜ注目されているか

推測 スピーカーではなくトラックパッドの振動モーターで音声を再生するという独創的なハックが話題を呼んでいる。Macをミュートしていても通知音が出る実用性と、ハードウェアの隠れた可能性を引き出す面白さが評価されていると考えられる。

どんな人に役立つか

MacBookのハードウェアハックや低レベルプログラミングに興味がある開発者向け。静音環境でさりげなく通知を受け取りたいMacユーザーや、プライベートAPIの活用例を学びたいiOS/macOS開発者にも参考になる。

技術的なポイント

  • macOSのプライベートフレームワーク「MultitouchSupport」を使って触覚モーターを直接制御している（非公開APIのため、macOSアップデートで動作が変わる可能性がある）。
  • macOSの音声合成で生成した音声に対して線形予測（LPC）を適用し、10msごとにフォルマント（声の特徴的な周波数）・音量・ピッチを抽出する。
  • 抽出した2つのフォルマント周波数をトーンとしてモーターに再生させることで、人の声に近い振動パターンを生成する。
  • 依存ライブラリなしの単一Swiftファイル（nospeaker.swift）で実装されており、コードが読みやすい。

試し方

  1. Force Touchトラックパッド搭載のMacBook（macOS 12以降のApple Silicon、またはmacOS 13以降のIntel）を用意する。
  2. curlスクリプト、リリースのzip、またはXcodeでビルドしてインストールする。
  3. ターミナルで ./nospeaker "hello there" を実行するとトラックパッドがしゃべる。
./nospeaker "hello there"

Hut-hzf/ung220z-tool

Trendshift 12位PythonGitHub ↗

自分のONU（光回線終端装置）から管理パスワードを取得するCLIツール

何ができるか

  • Telnetを使ってUNG220Z（光ファイバー終端装置）の現在の管理画面・Telnet・PPPoE・WiFiの認証情報を取得できる。
  • ontkit追加パッケージにより、中興（ZTE）・烽火（FiberHome）・ファーウェイ（Huawei）・九聯など複数メーカーのONUにも対応している。
  • ファームウェアのフィンガープリント識別（probeコマンド）で機種ファミリーを自動判定し、メーカー別のアクセス方法を提案する。
  • パスワードに特殊文字が含まれる場合の処理や、ログ出力時の認証情報マスキングに対応している。
  • Python 3.8以上の標準ライブラリのみで動作するため、追加インストールなしで使用できる。

なぜ注目されているか

推測 光回線の管理パスワードを忘れてもルーターの設定画面にログインできなくなるケースが多く、プロバイダへの問い合わせなしで自己解決できるツールへの需要は高い。また中国市場の複数メーカーのONUを一つのツールで扱える点も注目を集めている可能性がある。

どんな人に役立つか

自宅や事務所のONUの管理パスワードを忘れた人、宽带（ブロードバンド）設定を別の機器に移行したい人、またはネットワーク機器のセキュリティを自己点検したい人に役立つ。自分が所有するデバイス上での使用を前提としている。

技術的なポイント

  • Telnetプロトコルを使ってONUの設定ページにアクセスし、現在の資格情報を読み出す。
  • ontkit追加パッケージはプローブコマンドでファームウェアのファミリーを識別し、メーカーごとに異なるコマンド体系を切り替える。
  • Telnetの有効化に使うエンドポイントが404を返す場合は別のファームウェアファミリーと判定し、ファミリー別の排障（トラブルシューティング）提案を出す仕組みを持つ。
  • パスワードに特殊文字が含まれる場合の処理をv1.2で修正し、コミュニティ報告を元にサイレント障害バグも複数修正されている。

試し方

  1. Python 3.8以上がインストールされていることを確認する。
  2. リポジトリをクローンまたはダウンロードする。
  3. スクリプトを実行し、ONUのIPアドレスを引数として渡す。
  4. 表示された認証情報を確認する。

ivall/xcl

Trendshift 14位RustGitHub ↗

Xbox Series X|Sのゲームバイナリ（GDK形式）をWindows上でCPUエミュレーションなしに動かす互換レイヤー

何ができるか

  • Xbox Series X|S向けのアンパック済みゲームファイル（GDK形式）をWindows上でネイティブ実行できる。
  • コンソール専用のシステムライブラリを再実装することで、ゲームコードがOSの機能を呼び出せるようにする。
  • コンソール用RDNA2 GPUシェーダーをDXIL（DirectX Intermediate Language）に変換し、PC用D3D12 GPUで動作させる。
  • ゲームフォルダを改変せず、書き込みはオーバーレイ層に行くため元データが保護される。
  • xcl run・xcl inspect・xcl disasm・xcl shadersなどのCLIコマンドでゲームの起動・解析・シェーダー変換が行える。

なぜ注目されているか

推測 Xbox Series X|Sのゲームライブラリを、コンソール本体なしにWindows PCで動かす技術的挑戦として注目されている。CPUエミュレーションなしに実行できるアーキテクチャの類似性を活用したアプローチは、実行速度面でも優れており、370件以上の自動テストが品質を担保している点も評価されている。

どんな人に役立つか

Xbox Series X|Sのゲームアーカイブや互換性研究に興味のある開発者・研究者に向く。またRustによるシステムプログラミングやGPUシェーダーコンパイル技術を学びたいエンジニアにとっても参考になる。自分が所有する正規購入ゲームのアンパック済みファイルが前提。

技術的なポイント

  • RustでXbox GDKのシステムライブラリを再実装し、ゲームコードが呼び出すコンソールAPIをPC上で処理する。
  • RDNA2用シェーダーをDXIL（DirectX中間言語）にトランスパイルし、Windows SDK付属のDXCコンパイラでPC用シェーダーに変換する。
  • D3D12のShader Model 6.6とメッシュシェーダー対応GPUが必要で、Windows 10ではAgility SDKの追加配置が求められる。
  • 各実行ごとにreport.jsonが生成され、シェーダー変換の成否やゲーム動作ログが記録される。

試し方

  1. Rust toolchain・Windows SDK（DXCコンパイラ含む）・D3D12対応GPU（SM 6.6・メッシュシェーダー対応）を用意する。
  2. リポジトリをクローンする。
  3. cargo build --release --workspaceでビルドする。
  4. xcl run <ゲームフォルダパス>でゲームを起動する。
cargo build --release --workspace
xcl run <game_path>
xcl inspect <game_path>
xcl disasm <file>
xcl shaders <game_path>
