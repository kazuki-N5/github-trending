Albert-Weasker/niubigeo

Trendshift 3位TypeScriptGitHub ↗

AIブランド可視性を自己ホストで測定するオープンソースツール

何ができるか

  • ドメインを入力するだけで、複数のAIモデルがそのブランドをどう説明するかを比較できる。
  • AIの回答内で言及された競合他社やキーワードの一覧を確認できる。
  • 各結果の元となるAIの回答とソース引用をそのまま参照でき、ブラックボックスにならない。
  • ブランド名を出さずにキーワード単位でテストし、独立した履歴を保持するキーワードモニタリング機能がある（ベータ版）。
  • 測定結果をCSVやJSONにエクスポートしたり、差分ビューで複数回の測定結果を比較したりできる。
  • 計測を繰り返し実行またはスケジュール化でき、変化を時系列で追跡できる。

なぜ注目されているか

推測 GEO（Generative Engine Optimization、AIが検索結果を生成するエンジン向けの最適化）への注目が高まる中、自社ブランドがAIにどう認識されているか可視化したいニーズが増えている。既存のSaaSツールはブラックボックスなスコアしか提供しないが、このツールは元の回答を直接見せるため透明性が高い点が評価されている。推測 オープンソースかつ自己ホスト可能なため、APIコストだけで利用できることも支持される理由と考えられる。

どんな人に役立つか

自社ブランドや製品がChatGPTなどのAIにどう紹介されているかを把握したいマーケターやプロダクトマネージャー。GEO施策の効果を測定したいWebマーケティング担当者やSEOエンジニア。

技術的なポイント

  • Node.js 22.13以上が必要で、OpenRouter APIキーを使って複数のLLM（大規模言語モデル）にリクエストを送る。
  • バックエンドはnpmで依存関係をインストールし、`npm run server`で起動するNode.jsサーバー構成。
  • Dockerにも対応しており、コンテナ化して簡単にデプロイできる。
  • オフライン回答とWebサーチ付き回答を別々に記録・比較することで、AIの回答ソースの違いを追跡できる。

試し方

  1. Node.js 22.13以上とOpenRouter APIキーを用意する。
  2. `npm ci`で依存関係をインストールする。
  3. `npm run server`でサーバーを起動する。
  4. ブラウザでlocalhost:8787を開いてダッシュボードを使用する。
npm ci
npm run server

NotRexed/Hookshot

Trendshift 4位C++GitHub ↗

ゼルダOoTをPCでネイティブ実行する静的リコンパイルツール（README 未確認）

README を読めなかったため、トレンドページの情報だけで書いています。

何ができるか

  • ゲームのARM64コードをCに変換してPCネイティブバイナリとしてコンパイルする静的リコンパイル（エミュレーターなし）を実現する。
  • サウンド、コントローラー・キーボード操作、セーブデータに対応している。
  • フレーム生成（2〜4倍）、解像度スケーリング、アップスケーリング、ゲームスピード調整などのゲーム内メニューを備える。
  • ウルトラワイドモードとFPSカウンターをサポートする。
  • Switch 2のAmpereシェーダーをMaxwell経由でSPIR-V（VulkanのGPU命令形式）に変換する。

なぜ注目されているか

推測 Nintendo Switch 2版「ゼルダの伝説 時のオカリナ」が静的リコンパイルという手法でPC上でエミュレーターなしに動作するとして話題になっている。高フレームレートやアップスケーリングなどPC向けの拡張機能を備えており、ゲーム技術面での注目も集めている。推測 静的リコンパイル技術そのものへの学習・研究目的でも関心を持たれていると考えられる。

どんな人に役立つか

自分で合法的に入手したゲームをPCで高画質・高フレームレートでプレイしたいユーザー。静的リコンパイルやVulkanグラフィックスバックエンドの実装を学びたい開発者。

技術的なポイント

  • 静的リコンパイルとはゲームのバイナリコードを別アーキテクチャ向けのコードに事前変換し、エミュレーターなしで実行する技術。
  • グラフィックスAPIにVulkan 1.3（メッシュシェーダー対応）を使用しており、現時点ではNVIDIA GPUのみテスト済み。
  • ビルドには約40分かかり、約60GBの空きディスクが必要。
  • Windows 10/11（64ビット）またはglibc 2.35以上の64ビットLinuxで動作する。
  • ビルドツールとしてPythonスクリプト（`nx2/make_game.py`）によるCLIビルドもサポートする。

試し方

  1. GitHubのReleasesページからHookshot Builderをダウンロードする（Linuxの場合はAppImage）。
  2. ビルダーに自分のゲームの`.nup`ファイル、またはromfsとexefsフォルダを指定する。
  3. 言語と出力フォルダを選択し、ビルドを開始する（約40分かかる）。
  4. 出力フォルダの`hookshot.exe`（Linuxでは`hookshot`）を起動する。

JenkinWoo/sheeridVerify

Trendshift 5位JavaScriptGitHub ↗

SheerID認証フローをブラウザ自動化で学習・テストするNode.jsツール

何ができるか

  • 現在の認証ステップに応じてブラウザフォーム入力か書類アップロードのパスを自動的に選択する。
  • WebダッシュボードからジョブのPNG・JPEG・PDFファイルのアップロードを管理できる（ファイルの生成・改変はしない）。
  • ジョブの作成・キュー登録・停止・再開・削除を行え、同時実行数を設定できる。
  • ダッシュボードはパスワード・セッションCookie・オリジン確認・CSRFトークンで保護されている。
  • 読み取り専用のステータス確認のみ自動リトライし、書き込み操作は安全のためリトライしない。

なぜ注目されているか

推測 SheerID（学生・軍人・医療従事者などの資格確認サービス）の認証フローを自動化する仕組みへの関心からトレンド入りしていると考えられる。教育・研究・テスト目的と明記されており、認証ワークフローの仕組みを学ぶためのリファレンス実装として注目されている可能性がある。

どんな人に役立つか

SheerIDの認証フローの仕組みを学びたい学生や開発者。自分で認可を受けた範囲での検証ワークフローの自動化やテストを行いたいエンジニア。

技術的なポイント

  • Node.js 22.15以上が必要で、依存関係をインストールしてからローカルWebサーバーを起動する構成。
  • ブラウザ自動化でフォーム入力や書類アップロードを行うため、別途ブラウザのインストールが必要。
  • ダッシュボードは127.0.0.1:8787でローカルにのみ公開され、公開サーバーにはHTTPS必須。
  • テストはモックエンドポイントを使用したオフラインテストで、実際のAPIを叩かない。
  • オプションでプロキシ経由の接続をサポートしており、リクエストのルーティングをカスタマイズできる。

試し方

  1. Node.js 22.15以上をインストールする。
  2. 依存関係をインストールし、ブラウザもセットアップする。
  3. サンプル設定ファイルをコピーして自分の認可済み情報を入力する。
  4. サーバーを起動し、ブラウザで127.0.0.1:8787にアクセスする（デフォルトのパスワードは必ず変更すること）。

SwitchゲームをiPhone/iPadでネイティブ実行するmacOSランチャーアプリ

何ができるか

  • macOS（またはWindows）上でGUIを操作するだけでSwitchゲームをAppleデバイス向けにビルドでき、ターミナル操作が不要。
  • ゲームライブラリ管理とゲームごとの起動オプション設定ができる。
  • コントローラーとタッチコントロールの両方に対応している。
  • iCloud Driveを通じたクラウドセーブに対応している。
  • Switch 2のゲームファイル（.nupなど）にも対応している。
  • iPhoneとiPadで共通のシェルアプリを使い、同一ビルドで両デバイスをサポートする。

なぜ注目されているか

推測 SwitchゲームをiPhone/iPadで動かせるという注目度の高い機能と、GUIで一クリックでビルドできる手軽さがSNSやコミュニティで広まりトレンド入りしていると考えられる。nxnativeというプロジェクトのコミュニティフォークであり、より使いやすいフロントエンドを提供している点も評価されていると推測される。

どんな人に役立つか

自分で入手したSwitchゲームをiPhone/iPadで遊びたいユーザー。静的リコンパイルやAppleプラットフォーム向けゲームビルドの仕組みに興味のある開発者。

技術的なポイント

  • エミュレーターではなく静的リコンパイル（ゲームコードをネイティブバイナリに事前変換する手法）でゲームを実行するnxnativeを基盤としている。
  • iOS/iPadOS 26以上が対象で、NVNゲームのビルドにはXcode 27.2が必要。
  • iOSデバイスへのインストールには、Macとデバイスのペアリングが必要。
  • .NET SDK 10が必要な依存関係の一つとして挙げられている。
  • ランチャー自体は署名なし（Unsigned）のため、インストール方法に制限がある。

試し方

  1. macOS 13以上のAppleシリコンMacを用意し、Xcode 27.2と.NET SDK 10をインストールする。
  2. GitHubのReleasesページからランチャーアプリをダウンロードする。
  3. 自分のゲームダンプと`prod.keys`を用意してランチャーに登録する。
  4. ビルドを実行し、完成したアプリをiPhone/iPadにインストールする。

sostenesfreitas/ocarina-recomp

Trendshift 11位CGitHub ↗

エミュレータ不要でOcarina of TimeをWindowsネイティブ実行するファンプロジェクト

何ができるか

  • ゲームのARM64コードをCに変換し、Vulkan対応のランタイムでWindowsネイティブ実行できる
  • NVN 2グラフィックスAPIの呼び出しをVulkan（GPU向け低レベルAPIの一つ）にマッピングする
  • エミュレータ（LichiiやEden）からのセーブデータをインポートできる
  • Windowsの言語設定に従い、F1メニューから言語を切り替えられる
  • ZIP形式のインストーラー、PowerShellスクリプト、手動手順の3通りのビルド方法を提供する
  • オープニング、コキリの森、サウンド、コントローラー入力、セーブ、ビデオ再生が動作確認済みである

なぜ注目されているか

推測 エミュレータを使わずに商業ゲームをネイティブ動作させる「リコンパイル（再コンパイル）」技術がゲームファンや逆アセンブル愛好者の間で注目を集めており、特にNintendo 64系タイトルへの応用例として話題になっている。推測 Switch 2向けのVulkan変換という最新GPUへの対応も技術的関心を高めていると考えられる。

どんな人に役立つか

自分でゲームの合法的なコピーを所持しているOcarina of Timeファンや、リコンパイル・グラフィックスAPI変換技術に興味があるゲーム開発者・CS学生に向いている。NVIDIA GPU（Vulkan 1.3・メッシュシェーダー対応）とWindows 10/11（64ビット）環境が必要である。

技術的なポイント

  • ARM64のゲームコードを静的にCへ変換（リコンパイル）し、ホストCPUでネイティブ実行する手法を採用している
  • NVN 2（NVIDIAのゲーム向け独自API）の呼び出しをVulkan 1.3に変換してレンダリングする
  • Ampereアーキテクチャ向けシェーダーをMaxwellに対応させ、SPIR-V（Vulkanのシェーダー中間言語）に変換するために改造版Ryujinxを使用している
  • コンソールのシステムソフトウェア相当の機能をランタイムライブラリとして実装し、HLEという手法でゲームを動かす
  • プロジェクトはGPL-3.0ライセンスで公開されており、コントリビューション（貢献）はCONTRIBUTING.mdのガイドラインに従う

試し方

  1. 64ビットWindows 10/11とAVX2対応CPU、Vulkan 1.3・メッシュシェーダー対応のNVIDIA GPU、16GB以上のRAMを用意する
  2. 自分が所持するOcarina of Timeバージョン1.1.1のROMファイルを準備する
  3. リポジトリのREADMEに記載のZIPインストーラー、PowerShellスクリプト、または手動手順のいずれかでビルドする
  4. ビルド完了後にゲームを起動し、F1またはEscでオプションメニューを開いて設定を確認する

なぜ注目されているか

推測 Tauriという軽量なクロスプラットフォームフレームワーク（RustとWebフロントエンドを組み合わせるツール）をTypeScriptとReactと組み合わせた実装例として、技術的な学習目的で注目されていると考えられる。推測 非公式クライアントの実装パターンやhls.jsを使った動画再生の実例としても参考にされている可能性がある。

技術的なポイント

  • AndroidビルドにはAndroid SDK・NDK・JDK 17が必要で、pnpmのnpmrcでnode-linker=hoistedを設定する必要がある

試し方

  2. pnpm installで依存関係をインストールする
  3. デスクトップ版はpnpm app:devで開発サーバーを起動するか、pnpm app:buildでインストーラーをビルドする
  4. Androidビルドの場合はAndroid SDK・NDK・JDK 17を用意し、pnpm android:initの後にpnpm android:devまたはandroid:buildを実行する

AIエージェント向けのヘッドレス3D・VFXエンジン（リサーチプレビュー）

何ができるか

  • シーンをコード（JSON・TypeScript・Python）で記述してGPUでレンダリングでき、動画モデルを使わない
  • 百万羽の鳥の群れシミュレーションや、実写映像へのVFX合成などのサンプルが用意されている
  • GPUによる液体シミュレーション（水のシミュレーション）をサポートしている
  • 光の伝播プログラムでシュワルツシルト・レンズイング（ブラックホールによる光の屈折）を近似できる
  • BlenderのEEVEEと比較した速度ベンチマークが公開されており、特定条件下で1.4〜1.7倍高速とされている

なぜ注目されているか

推測 AIエージェントがコードでシーンを記述して自律的にレンダリングできるという設計コンセプトが、AIワークフロー自動化の文脈で注目されていると考えられる。推測 RustとSlang（GPUシェーダー言語）でVulkanとMetalの両方に対応するという技術選択も、高性能グラフィックスへの関心を持つ開発者を惹きつけている可能性がある。

どんな人に役立つか

3DレンダリングやVFXのパイプラインをプログラムで自動化したいAIエージェント開発者、またはRustとGPUプログラミング（Vulkan・Metal）に興味があるCS学生や研究者向けである。Apple SiliconまたはNVIDIA GPU（Vulkan Ray Queriesサポート）が必要である。

技術的なポイント

  • RustとSlang（Microsoftが開発したGPUシェーダー言語）で実装されており、VulkanとMetalの両APIで動作する
  • シーン記述はJSON・TypeScript・Pythonで記述でき、エージェントがコードからレンダリングを制御しやすい設計になっている
  • Blender EEVEEとの比較ベンチマーク（同等品質での比較ではないと注記あり）でfinalスチルが約1.4〜1.7倍高速とされているが、パストレーシングはCyclesより遅い結果が示されている
  • フォグ・ボリュームは現バージョンで未対応であり、大規模シーンではメモリ不足になる場合がある
  • オプションのBlenderブリッジはGPL（オープンソースライセンスの一つ）でライセンスされており、本体とは別ライセンスである

試し方

  1. Apple SiliconまたはNVIDIA GPU（Vulkan Ray Queries対応）とffmpegを用意する
  2. Linux・Windows・MacのそれぞれのREADMEに記載のインストール手順に従いvorkをセットアップする
  3. vork init my-shotでプロジェクトを初期化する
  4. scene.jsonを編集してシーンを記述し、vork render scene.json --profile std/draft --out render.pngでレンダリングする
  5. vork helpでシーンの概念やフィールドのドキュメントを確認する
vork init my-shot
vork render scene.json --profile std/draft --out render.png
vork help

AIモデルが最初にリファクタすべきファイルを順位付けするリンター

何ができるか

  • ASTによる静的解析（複雑度・ネスト深度など）とAIモデルによる意味的判定（命名の適切さなど）の2種類のチェックができる
  • ファイルをコードの乱雑さ・gitの変更頻度・サイズで順位付けし、最優先で直すべき箇所を特定できる
  • `jevlint pr`と`jevlint commits`でブランチやコミット範囲のスコア変化をレビューできる
  • ast-grepパターンと自然言語の質問でカスタムルールを作成できる
  • 可読性・クリーンコード・SOLID・セキュリティ・ドキュメントなどのプリセットがTOMLで提供される
  • Claude CodeやCodexにパイプして自動修正でき、`jevlint fix`でエージェントを呼び出してリスコアできる

なぜ注目されているか

推測 AIコーディングエージェントの普及に伴い、大規模レガシーコードベースのリファクタリング優先度付けをAIに任せたいニーズが高まっている。推測 Claude CodeプラグインやCI連携（SARIF・GitHub Annotations対応）など実用的なエコシステムとの統合が充実している点が注目を集めている。

どんな人に役立つか

レガシーコードベースを抱えるチームやCI/CDパイプラインでコード品質をゲートしたい開発者、AIエージェントと組み合わせてリファクタリングを自動化したいエンジニアに向いている。

技術的なポイント

  • AST（抽象構文木）解析でコードの複雑度・ネスト深度などを定量的に測定する
  • TypeSafe AIのJevなどのAIモデルを判定エンジンとして使い、命名の適切さなどを評価する（`--ast-only`以外はソースコードを外部送信する）
  • SARIF形式とGitHub Annotationsに対応しており、CIでスコアによるビルドゲートを設定できる
  • `fail_under`と`baseline`・`audit --new`の組み合わせでレガシーコードベースへの段階的導入ができる

試し方

  1. jevlintをインストールする
  2. リポジトリのルートでjevlintを実行し、スコアの高いファイルを確認する
  3. `jevlint fix`を実行してAIエージェントによる自動修正を試す
  4. CIに組み込む場合は`fail_under`でスコアのしきい値を設定する
