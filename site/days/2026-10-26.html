elayadesign/ai-design-skills

Trendshift 2位GitHub ↗

AIコーディングツール向けの自己完結型デザインスキル集

何ができるか

  • Claude Code・Cursor・Codex・Windsurfなど複数のAIコーディングツールに対応したスキルを提供する。
  • landing-page-designスキルはランディングページをゼロから構築し、タイポグラフィ・スペーシング・角丸・モーションの視覚システムを定義する。
  • design-to-motionスキルは静的デザインをアニメーションに変換し、X向けMP4と800×500のGIFとして書き出す。
  • 各スキルはフォルダ単位で独立しており、必要なものだけを個別にインストールできる。
  • デザイン値（フォント・カラー・スペーシング・モーション）はスキルファイルの一箇所にまとまっており、フォークして編集できる。

なぜ注目されているか

AIコーディングツールに渡すだけでデザイン作業を自動化できる実用的なスキルセットとして公開されており、MIT ライセンスで帰属表示不要の点も導入しやすい。landing-page-design と design-to-motion という異なる用途の2スキルが揃っている点で即戦力として使える。推測 既存サイトのリニューアル向けの別リポジトリも存在するとされており、今後スキルの拡充が期待できる。

どんな人に役立つか

Claude Code や Cursor などのAIコーディングツールを使ってランディングページや動画コンテンツを制作したいデザイナーや開発者に向いている。既製のデザインルールを活用して短時間で成果物を生みたいフリーランサーや小規模チームにも適している。

技術的なポイント

  • 各スキルはSKILL.mdファイルとして提供され、各ツールのルールファイル（.cursor/rules/、AGENTS.mdなど）に配置して使う。
  • Claude Codeでは.claude/skills/フォルダにスキルフォルダをコピーするだけでインストールできる。
  • design-to-motionはMITライセンスの3つのプロジェクトから引用したモーションルールを採用している。
  • カスタマイズ箇所はスキルファイル内の一セクションに集約されており、フォークして値を書き換えるだけで独自ブランドに適用できる。

試し方

  1. リポジトリをクローンするか、使いたいスキルのフォルダをダウンロードする。
  2. Claude Codeの場合はスキルフォルダを.claude/skills/にコピーする。
  3. Cursorの場合はSKILL.mdを.cursor/rules/に配置するか、Settings → Rules for AIに貼り付ける。
  4. CodexやWindsurfなどその他のツールはSKILL.mdをツールのルールファイル（AGENTS.md、.windsurfrules等）に追加する。
  5. Claude.aiではSKILL.mdをプロジェクトにアップロードするか、チャットに添付して使用する。

JustAResearcher/gpu-unlock-ada

Trendshift 3位CGitHub ↗

RTX 4090等のテンソル演算制限をLinuxで解除するカーネルモジュール

何ができるか

  • Linuxカーネルモジュールとしてinitramfsで動作し、NVIDIAドライバがバインドする前にSMスピードセレクトオーバーライドを適用する。
  • RTX 4090（10de:2684）でFP16/FP32およびBF16/FP32テンソル命令スループットを約2倍（約165→330 TF/s）に向上させることを確認している。
  • RTX 4070 Ti SUPER（10de:2705）ではFP16/FP32とTF32/FP32の発行レートが約2倍になることを確認している。
  • RTX 4060 Ti 16GB（10de:2805）は実験的サポートで、SM速度レジスタの変更は確認済みだが同一カードでのベースライン比較は未実施。
  • ファームウェアペイロードをSHA-256で検証し、FLR（Function Level Reset）を実施してからNVIDIAドライバを起動させる安全手順を実装している。
  • ファームウェアはビルド時にローカル生成・ハッシュ検証されるため、プリビルドバイナリは配布されない。

なぜ注目されているか

コンシューマー向けGPUにハードウェアレベルで制限されているテンソル演算のスループットをソフトウェアで解除できる稀有なツールであり、ローカルAI推論や研究用途でのコスト対性能比向上に直結する。GPU内部のSMスピードセレクト機構をLinuxカーネルモジュールとして操作する技術的アプローチが注目されている。推測 NVIDIA公式サポート外の操作であるため、動作保証やドライバ更新後の互換性には注意が必要と考えられる。

どんな人に役立つか

ローカルでLLM推論や機械学習ワークロードを実行しており、RTX 4090などのコンシューマーGPUのテンソル演算性能を最大化したい研究者や開発者に向いている。Linuxカーネルモジュールのビルドやinitramfsの設定経験がある中級以上のユーザーを想定している。

技術的なポイント

  • カーネルモジュールはinitramfsステージで実行され、NVIDIAドライバのバインド前にGPUのファームウェアトランザクションを実行する。
  • AD102ペイロードとデバッグブーター解析はTOTORONG/AD103_win_unlockerに由来し、LinuxモジュールはZagitta/gpu-unlockから派生している。
  • ビルド時にピン留めされたNVIDAの入力ファイルをダウンロードしてハッシュ検証することでサプライチェーン攻撃を防ぐ設計になっている。
  • カーネルコマンドラインオプション（gpu_unlock.targets=）でターゲットGPUのPCIアドレスを指定して動作させる。
  • カーネルモジュールとパッケージングはGPL-2.0-only、NVIDIAファームウェアはNVIDIA独自ライセンスが適用される。

試し方

  1. リポジトリをクローンしてソースからビルドする（make install、またはArch/Debian/RPM向けターゲットを使用）。
  2. 初回試行前にコールドパワーオフ（完全電源断）を行い、ウォームリブートを避ける。
  3. カーネルコマンドラインにgpu_unlock.targets=をPCIアドレスとともに追加してターゲットGPUを指定する。
  4. initramfsにモジュールを組み込み、NVIDIAドライバより前にロードされるよう設定する。
make install

TauricResearch/TradingAgents

Trendshift 12位PythonGitHub ↗

マルチエージェントLLMによる金融トレーディング研究フレームワーク

何ができるか

  • ファンダメンタルズ・センチメント・ニュース・テクニカルの4つのアナリストエージェントが並列で分析を行う。
  • 強気・弱気の2つのリサーチャーエージェントがアナリストの分析結果を巡って議論し、多角的な視点を提供する。
  • トレーダーエージェントがレポートと議論を元に売買タイミングとポジションサイズを決定する。
  • リスク管理エージェントとポートフォリオマネージャーエージェントがトレーダーの提案を審査・承認または却下する。
  • Yahoo Financeを通じて米国・香港・日本・インド・中国A株・暗号資産などグローバル市場に対応している。
  • 過去のトレード決定と振り返りを記憶ログとして保持し、後続の実行に活かすパーシスタンス機能を持つ。

なぜ注目されているか

単一エージェントではなく、実際の証券会社の組織構造（アナリスト・リサーチャー・トレーダー・リスク管理）を模倣したマルチエージェント設計が学術的に注目されており、arXiv（2412.20138）にも掲載されている。SECのEDGARから取得した米国ファンダメンタルズデータを利用することでルックアヘッドバイアスを避けたバックテストが可能な点が研究用途として差別化されている。推測 対応するLLMプロバイダーの幅広さ（OpenAI・Anthropic・Google・DeepSeekなど）から、特定のモデルへの依存を避けた設計思想が伺える。

どんな人に役立つか

LLMを使った金融トレーディング戦略の研究や実験に興味があるデータサイエンティストや機械学習エンジニアに向いている。マルチエージェントシステムの設計パターンをファイナンス領域で学びたい学生や研究者にも適している。なお、本フレームワークは研究目的であり、実際の投資アドバイスを意図するものではないとREADMEに明記されている。

技術的なポイント

  • Python 3.11以降が必要で、pip install .またはuv、あるいはDockerでセットアップできる。
  • OpenAI・Google・Anthropic・DeepSeek・Ollamaなど多数のLLMプロバイダーに対応しており、OpenAI互換エンドポイントも使用できる。
  • SECのEDGARから財務データを取得することでバックテスト時のルックアヘッドバイアスを排除している。
  • 対話型CLIと非対話型モード（フラグ・環境変数）およびPython API（TradingAgentsGraph）の3つのインターフェースを提供している。
  • チェックポイント再開機能により中断されたバックテストを途中から継続できる。

試し方

  1. Python 3.11以降がインストールされていることを確認する。
  2. リポジトリをクローンしてpip install .でインストールする（またはuvやDockerを使用）。
  3. 使用するLLMプロバイダーのAPIキーを環境変数に設定する。
  4. 対話型CLIを起動して分析したいティッカーシンボルと日付を入力する。
pip install .
pip install uv && uv sync

yetone/magpie

Star History 18位★ +5,721（週）GitHub ↗

複数AIコーディングエージェントのモデルを一元管理するゲートウェイ

何ができるか

  • Claude Code、Codex、Gemini CLI、OpenCodeなど複数のコーディングエージェントで使用するモデルを一箇所で切り替えられる
  • APIキー、ローカルモデル、または署名済みサブスクリプション（Claude、ChatGPT、Copilot等）を利用できる
  • ルーティンググループでsmart、order、rotate、usage、paceモードによるフェイルオーバーとリクエスト分散を実現し、インテントルーティングでターンごとに最適なモデルを選択できる
  • リクエストがマシンを離れる前に秘密情報や個人データをプレースホルダーに置換し、返信時に復元するプライバシーマスキング機能を持つ
  • Bunで動作するプラグインシステムによりプロバイダーの追加やリクエスト・返信を編集するゲートウェイミドルウェアの実装が可能
  • トークン数、コスト、クォータを追跡し、ローカルネットワークへのゲートウェイ共有やDocker実行にも対応する

なぜ注目されているか

複数のAIコーディングエージェントを使い分けるエンジニアが増える中、それぞれのモデル設定を個別に管理する手間を解消するためのゲートウェイとして位置づけられている。プロファイル機能で複数のモデル構成を切り替えられるため、用途に応じたモデル選択を効率化できる。プライバシーマスキング機能により、機密情報を含むコードベースでも外部モデルを安全に活用できる可能性がある。

どんな人に役立つか

Claude Code、Codexなど複数のAIコーディングエージェントを日常的に使用しているエンジニアで、モデルの一元管理や切り替えを効率化したい人に向いている。コストやクォータを複数アカウント・モデルにまたがって管理したい人や、リクエストのルーティングをカスタマイズしたい上級ユーザーにも適している。

技術的なポイント

  • ローカルゲートウェイを127.0.0.1:3425で起動し、各エージェントの設定ファイルを直接編集してモデルを切り替える仕組みで動作する
  • メニューバーアプリ、ウィンドウ、TUI、Web UI、CLIの複数インターフェースを提供するMITライセンスのソフトウェア
  • Bunで動作するプラグインシステムにより、プロバイダーの追加やゲートウェイミドルウェアとしてのリクエスト・返信編集が可能
  • テレメトリは匿名の日次使用ピングのみで、SettingsまたはDO_NOT_TRACK=1でオプトアウトできる

  • パラメータ・アセンブリ・板金機能も搭載している

なぜ注目されているか

オープンソースのパラメトリック3D CADアプリケーションとしてRustで実装されており、高速動作と安全性が期待できる。MCPサーバーとして起動することでAIエージェントからCAD操作を自動化できる点は他のCADソフトにはない独自の機能である。76件の公開参照パーツのうち75件が期待値と一致しており、実用的な精度を確認済みとREADMEに記載されている。

どんな人に役立つか

  • solidcraft-cli mcpコマンドでMCPサーバーを起動し、AIエージェントから操作できる
  • 操作はUIと共通のJSONコマンドリスト形式のスクリプトで記述できる
  • STEP・STL・3MF・glTFなど複数の3Dファイル形式に対応している
  • MITまたはApache-2.0のデュアルライセンスで提供されている

試し方

  1. リポジトリをクローンする
  2. cargo runコマンドでデスクトップアプリをサンプルパーツ付きで起動する
  3. MCPサーバーを使う場合はsolidcraft-cli mcpコマンドを実行する
cargo run
solidcraft-cli mcp

  • ハードコードの数値ではなく変数と数式でレイアウト関係を表現する
  • カードやダイアログなど様々なUIコンポーネントに対応している

  • リポジトリファイル・Storybookストーリー・URL・スクリーンショットを入力として使用できる

なぜ注目されているか

Appleの寸法仕様図にインスパイアされたスタイルでUIコンポーネントの仕様を自動生成できる点が特徴的である。Claude CodeやClaude.aiのスキルとして使えるため、AIエージェントを使ったデザインドキュメント作成のワークフローに組み込みやすい。テキストコンテンツを省くことで、コピーが変わっても仕様図の精度が保たれる設計になっている。

どんな人に役立つか

  • モーション機能はNode.js 18以上とffmpegを使ったヘッドレスレンダラーで動作する
  • Claude Motionアーティファクトでの使用に最適化されている
  • MITライセンスで提供されている

試し方

  1. リポジトリをクローンしてスキルフォルダを~/.claude/skills/にコピーする（Claude Code）
  2. またはスキルフォルダをzipにしてSettings→Capabilities→Skillsから追加する（Claude.ai）
  3. コンポーネントのソース（ファイル・URL・スクリーンショット）をエージェントに指示して仕様図を生成する
npx skills add enesozturk/dimensional-drawing

Till0196/coax

はてなブックマーク 3位3 usersGoGitHub ↗

TVチューナーの操作とストリーミングを行うデーモン・クライアント

何ができるか

  • チューナーデーモン（coaxd）とCLIクライアント（coax）の組み合わせでTV受信環境を構築できる
  • ISDB-T・ISDB-C・ISDB-S・ISDB-S3やDVB-T/T2・DVB-S/S2など複数の放送規格に対応している
  • チャンネルスキャンと周波数リストを使った自動チャンネルリスト生成ができる
  • Mirakurun・BonDriver・DVBv5・TVTest・EDCB形式にスキャン結果をエクスポートできる
  • BonDriverとしてTVTestやEDCBと連携できる
  • 内蔵ICカードリーダーへのPC/SCソケット経由アクセスに対応している

なぜ注目されているか

OS固有のUSBアクセス方法（WinUSB・IOKit・usbfs）やDVB API・BDA APIの差異を吸収し、Windows・macOS・Linuxで統一的なチューナー操作インターフェースを提供する点が特徴である。GoでCGO_ENABLED=0のままビルドできるためクロスコンパイルが容易で、既存のMirakurunやTVTest環境とも連携しやすい設計になっている。

どんな人に役立つか

日本のTV視聴環境（特にISDB系）を自前で構築したいユーザーに向いている。既存のMirakurun・TVTest・EDCB環境と連携させたい上級ユーザーにも適している。

技術的なポイント

  • Go 1.25以上で実装されており、CGO_ENABLED=0でLinux・Windows・macOSにクロスコンパイルできる
  • coaxdデーモンとcoaxクライアントはHTTP APIを介して通信する
  • USB・PCIe・Linux DVB・Windows BDAの異なるハードウェアアクセス方式を統一的に扱う
  • TSMFマルチプレックスとTLVストリーム（IP・UDP・MMTP・TLV-NIT）のパースに対応している
  • コードはApache-2.0またはGPL-2.0-or-laterのデュアルライセンスで提供されている

試し方

  1. Go 1.25以上をインストールする
  2. リポジトリをクローンしてcoaxとcoaxdをビルドする
  3. coaxd listでチューナー一覧を確認してcoax tuneでチューニングする
CGO_ENABLED=0 go build ./cmd/coax
CGO_ENABLED=0 go build ./cmd/coaxd
coaxd
coax list
coax tune
